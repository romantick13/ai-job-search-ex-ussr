# RFC-001 — Стек и отказ от зоопарка (фундамент ai-job-search-by)

Статус: proposed | Дата: 2026-10-18 | Рев. 2026-10-19: синхронизация с патчем 01, реестром schema v3 и фактическим набором доков | Рев. 2026-10-20: пути приведены к фактическому дереву репозитория (RFC/, config/, корень), патч 01 поглощён как Приложение A | Рев. 2026-10-20 (2): учреждены todo.md и handoff.md решением владельца — п. 2 §0 и список доков приведены к факту | Слит в DECISIONS.md: 2026-10-20 (3), решение владельца | Владелец: ThreeI
Scope: корень репозитория

## 0. Что изменилось в рев. 2026-10-19

1. **Шрифтовое требование отменено как ошибочное.** «Обязательный шрифт с
   поддержкой CJK/Cyrillic (DejaVu/Noto)» заменён на факт: встроенный в
   QuestPDF Lato 2.015 (SIL OFL 1.1) покрывает кириллицу из коробки
   (Приложение A). Настоящее железное
   правило — ЗАПРЕТ системных имён шрифтов в коде (на машине без Arial
   экспорт падает исключением, а не подстановкой). Noto-fallback — опция
   v1.1, в v1 дополнительные шрифты не возим. README и релиз-чеклист (п. 4)
   уже утверждают ровно это — RFC теперь не спорит с ними.
2. **§5 приведён к фактическому набору доков.** RFC-002 — раздел
   этого файла (поглотил RFC-002-A1). Отдельного RFC-003 не
   существует — слой порталов ведут config/registry.json + каталог +
   могильник. Призраки из старого списка (docs/AI_CONTEXT.md, docs/HANDOFF.md,
   docs/todo.md) не переносятся. Решением владельца от 2026-10-20 в корне
   учреждён рабочий файл PLAN.md (план работ, статус, гейты релиза, журнал);
   рев. (3) того же дня todo/handoff/CHANGELOG/release-checklist слиты в него;
   архитектурное описание — architecture.md в корне.
3. **Добавлены правила, принятые в доко-фазе:** реестр = единый источник
   правды, README-таблицы только генератором (tools/gen_readme_counters.py);
   данные и конфиг в %APPDATA%\ai-job-search-by\ (патч 05 — RFC-006, Приложение A); состав zip — по
   релиз-чеклисту п. 10.
4. Стек, версии, альтернативы, правила кода и Avalonia-грабли — без
   изменений; из железных запретов добавлен один (системные имена шрифтов).

## 1. Проблема

Upstream github.com/MadsLorentzen/ai-job-search (MIT) требует Claude Code
(Claude Pro/Max — официально недоступен в РБ из-за санкций) и тянет зоопарк:
TypeScript/Bun (порталы), Python (tools), LaTeX (CV/cover), плюс кандидаты
в харнесы на Go (opencode). Для продукта «поиск работы в Беларуси», который
владелец публикует для других людей, это неприемлемо: платный вход,
зоопарк рантаймов, тяжёлая установка на слабый ноут.

## 2. Решение

Единый стек, один рантайм:

- .NET 10 (net10.0), C#, OutputType WinExe, Nullable enable.
- UI: Avalonia 12.1.1 + Fluent, compiled bindings (x:DataType),
  CommunityToolkit.Mvvm 8.4.2 ([ObservableProperty]/[RelayCommand]).
- DB: SQLite + Microsoft.Data.Sqlite 10.0.10 + Dapper 2.1.79; без EF.
- DI: Microsoft.Extensions.DependencyInjection 10.0.10; интерфейсы на всё.
- Экспорт: Markdown → PDF (QuestPDF 2026.8.0) / DOCX
  (DocumentFormat.OpenXml 3.2.0) / HTML (Markdig 1.3.2). Кириллица — из
  коробки: встроенный в QuestPDF Lato 2.015 (SIL OFL 1.1) покрывает
  латиницу, греческий и кириллицу; CJK — не таргет v1. Железное правило
  вместо старого «поставь OFL-шрифт»: в экспортёрах ЗАПРЕЩЕНЫ системные
  имена шрифтов — `.FontFamily("Arial" / "Calibri" / "Segoe UI" / …)` на
  чистой машине даёт исключение «font family not found», а не подстановку;
  перед портом экспортёров — grep-аудит по списку из
  Приложения A (особое внимание: ExportStyles переносится 1:1).
  Fallback Noto через FontDiscoveryPath — опционально, не раньше v1.1.
- ATS-чек text-слоя PDF: UglyToad.PdfPig (Apache-2.0) + детерминированные
  правила проверки + детектор мусора/thinking-блоков.
- Тесты: xUnit 2.9.2; юниты без моделей, гейты с префлайтом; golden
  round-trip «PDF → PdfPig читает text-слой» и экспорт-тест на чистом
  CI-runner без установленных Arial/Calibri (Приложение A, §2.4).
- Харнес: СОБСТВЕННЫЙ оркестратор ApplyPipeline (фазовый паттерн:
  parse → eval → draft → reviewer → revise → export → ATS), checkpoint для
  resume. Внешний агент-харнес не используется.
- Python: только one-shot скрипты в tools/ с PYDOC-шапкой (UTF-8 без BOM),
  вне дистрибутива.
- Реестр: `config/registry.json` — единый источник правды по порталам и
  AI-провайдерам (schema v3); таблицы и счётчики README генерируются
  `tools/gen_readme_counters.py`, генерируемые блоки руками не правятся
  (CI-джоб docs-consistency).
- Данные и конфиг: `%APPDATA%\ai-job-search-by\`; установка и работа без
  прав администратора; миграция из «рядом с exe» — патч 05 (RFC-006, Приложение A).

Из upstream берём: LICENSE (дословно), идею контракта порталов,
референс воркфлоу. Markdown-промпты/команды/скиллы upstream НЕ переносятся
(решение владельца 2026-10-20) — источник логики при написании своих текстов
(WP-A). Не берём: TS/Bun cli, LaTeX-шаблоны, Python-рантайм tools,
claude-хвост (.claude/, AGENTS.md, CLAUDE.md, PROVENANCE.md — удалены
решением владельца 2026-10-20).

Железные запреты (не пересматривать без нового RFC): Entity Framework;
python.exe в runtime; параллельные LLM-запросы; cloud-only без локального
фолбэка; ключи в репозитории; TabControl (вьюхи теряют состояние —
Grid + IsVisible); ReactiveUI/Fody (багаж-заглушка); LaTeX/Typst в v1;
системные имена шрифтов в экспортёрах (Приложение A).

Правила кода с первого файла: граф-комментарии // FLOW / LIFECYCLE / STATE /
THREAD; документация = часть системы (код без обновлённых доков не
коммитится); каждая фаза = один коммит phase-N с доками в том же коммите.

Avalonia-грабли (выстраданные правила, соблюдать): Clipboard через
DataTransfer + DataTransferItem.CreateText + SetDataAsync; TextBox
оборачивать в ScrollViewer; StackPanel — Margin, не Padding;
PlaceholderText вместо Watermark; у каждого Window публичный ctor без
параметров. DI: один синглтон на две роли через фабрику
(AddSingleton<ISettingsProvider>(sp =>
sp.GetRequiredService<SettingsViewModel>()), иначе настройки расходятся
на два экземпляра).

## 3. Альтернативы (почему нет)

- opencode / иной агент-харнес (Go): даёт агентный цикл бесплатно, но тащит
  чужой рантайм и чужую модель поведения; наш пайплайн детерминированнее и
  тестируемее; зоопарк растёт. ОТКЛОНЕНО.
- Python-рантайм продукта: боль дистрибуции на чужом ноутбуке
  (venv/PATH/encoding); инфраструктуру пришлось бы переписывать с нуля.
  ОТКЛОНЕНО.
- LaTeX/Typst для CV: MiKTeX = гигабайты + CTAN-автоустановки на слабом
  ноуте; QuestPDF/OpenXml уже проверены на живых файлах. ОТКЛОНЕНО.
- Гибрид (TS-порталы upstream + C#-ядро): Bun/Node на публике = лишний
  рантайм; контракт портала тривиален, C#-реимплементация дешевле.
  ОТКЛОНЕНО.
- LiteLLM / самописный HTTP-watchdog прокси: каскад + префлайт живут
  in-proc (RFC-002), лишний эндпоинт не нужен. ОТКЛОНЕНО.

## 4. Последствия

- Апстрим-обновления кода не тянутся git-pull; синхронизация
  промптов/маркдауна — руками.
- QuestPDF = Community-лицензия (бесплатно для физлиц и организаций с
  оборотом до 1 000 000 USD в год; **госорганы и публичные компании не
  подпадают независимо от оборота**; при потере права — 90 дней на
  переход на Professional): раздел в README обязателен;
  `QuestPDF.Settings.License = LicenseType.Community` выставляется при
  старте до первого рендера; перед публикацией сверить LicenseType в
  PdfExporter.
- **Дефолтный шрифт PDF — Lato, уже встроенный в QuestPDF: кириллица
  покрыта, фича работает у русскоязычного юзера в первый же день, сборка
  не растёт. Ломают её не «квадратики», а системные имена шрифтов в коде —
  поэтому grep-гейт в релиз-чеклисте п. 4 и тест на чистом CI-runner.**

  с Avalonia); внутри README.txt + LICENSE + DISCLAIMER.md +
  TROUBLESHOOTING.md (релиз-чеклист п. 10).
- v1 целевая ОС — Windows 10 1809+ / Windows 11, x64; Avalonia
  cross-platform, но не обещаем в доках иное.
- PdfPig добавляет зависимость на WP экспорта/ATS, не раньше.
- Числа (порталы, лимиты, квоты) в доки не хардкодятся: реестр + рантайм +
  генератор; руками в README правится только проза.

# Приложение A — Поглощённый патч 01: QuestPDF — шрифты и лицензия

**Статус:** принят 2026-10-19, поглощён в RFC-001 как приложение | **Происхождение:** бывший `docs/patches/01-questpdf-fonts-and-license.md` (каталог patches/ удалён при переходе к дереву репозитория); тело ниже дословно.

## 1. Проблема (проверено по документации QuestPDF и лицензии v3.0)

1. **Кириллица в PDF работает из коробки.** QuestPDF по умолчанию использует
   встроенный шрифт Lato 2.015 (SIL OFL 1.1), который покрывает латиницу,
   греческий и кириллицу. Мой прежний тезис «квакозябры у пользователей» был
   ошибкой — реальный киллер другой.
2. **Настоящий киллер: системные шрифты в коде.** По умолчанию
   `QuestPDF.Settings.UseSystemFonts = false` (и это правильно для
   воспроизводимости). Если где-то в экспортёре указано
   `.FontFamily("Arial")` / `"Calibri"` / `"Segoe UI"` / `"Times New Roman"`,
   экспорт у пользователя падает **исключением** («font family not found»),
   а не подстановкой замены. У автора на машине Arial есть — баг не
   воспроизводится локально и вылезает в первый же релиз у части юзеров.
3. **Лицензия Community v3.0 (действует с 06.07.2026):** бесплатно для
   физлиц и организаций с оборотом < $1M; **госорганы и публичные компании
   не подпадают независимо от оборота**; при потере права — 90 дней на
   покупку Professional; редистрибуция — только compiled component
   производного приложения; нельзя удалять proprietary notices; фактическое
   «Built with QuestPDF» — можно.

## 2. Решение

### 2.1 Аудит шрифтов (сделать до порта экспортёров)

```bash
rg -n 'FontFamily\(\s*"(Arial|Calibri|Segoe|Times New Roman|Tahoma|Verdana)' src/
```

Результат должен быть пустым. Все явные имена — заменить на Lato (дефолт)
или на константу `PdfFonts.Base` со значением `"Lato"`. **Особое внимание:
константа `ExportStyles` переносится 1:1, и если в ней системные
имена, порт воспроизведёт киллер.**

### 2.2 Лицензия при старте (один раз, idempotent)

```csharp
// Program.cs / App.axaml.cs, до первого рендера
QuestPDF.Settings.License = QuestPDF.LicenseType.Community;
```

### 2.3 Fallback для символов вне Lato (опционально, v1.1)

Если в документах появляются эмодзи/CJK — подключать Noto-шрифты файлами в
приложение (не системные):

```csharp
// скан каталога с шрифтами при старте
QuestPDF.Settings.FontDiscoveryPath = "resources/fonts";
// или явно:
FontManager.RegisterFontsFromDirectory("resources/fonts");

// fallback-цепочка в стиле по умолчанию страницы
page.DefaultTextStyle(s => s.FontFamily("Lato", "Noto Sans", "Noto Emoji"));
```

В v1 дополнительных шрифтов **не возим**: Lato уже внутри QuestPDF, размер
сборки не растёт. Noto — отдельное решение после первого реального кейса.

### 2.4 Тесты

1. Golden-тест: экспорт резюме с кириллицей → PdfPig читает текст-слой,
   строки совпадают (round-trip).
2. Тест на «чистой» среде: CI-runner без установленных Arial/Calibri —
   экспорт не должен падать (ловит системные имена, просочившиеся в код).
3. Тест: `Settings.License` выставлен до первого `Document.Create`.

## 3. Что в документы

* README (раздел «Юридическая сторона»): формулировка про госорганы,
  публичные компании и 90-дневный переход — уже внесена.

# RFC-002 — AI-цепочка: каскад провайдеров, профили me/public, префлайт (+ free-tier OrcaRouter)

Статус: proposed | Дата: 2026-10-19 | Слит в DECISIONS.md: 2026-10-20 (3), решение владельца | Владелец: ThreeI
Scope: корень репозитория
Слияние: **RFC-002-A1 (orcarouter-free-tier) поглощён в §3** и больше не ведётся отдельным файлом.

## 0. Что изменилось при слиянии

1. A1 вошёл целиком как §3 «Механика free-tier OrcaRouter»; его «проблема» влилась в §1, альтернативы — в §4, последствия — в §5, константы — в §6.
2. В таблице каскада числа 50/800 перестали быть фактом навсегда: лимит читается в рантайме (§3.1), числа — только ориентир на дату.
3. Политика 429 уточнена: 429 на free = «этот провайдер недоступен», каскад идёт к следующему; авто-переход на платные модели того же ключа запрещён (§3.3).
4. Backoff при 429 на free — фиксированный по Retry-After, один повтор; адаптивная лестница 5→60 остаётся только для прочих провайдеров и 429 без заголовка (§3.3).
5. Окно квоты зафиксировано: суточный сброс **00:00 UTC**, локальный счётчик синхронизируется с той же точкой (§3.4).
6. Непубликуемый лимит размера промпта нижней ступени → упреждающий субчанк-бюджет + обрезка резюме до релевантного + один ретрай 413 с делением пополам (§3.5).
7. `rate-limit.json`: путь уточнён — каталог данных приложения (`%APPDATA%\ai-job-search-by\`) с миграцией из «рядом с exe» (патч 05 — RFC-006, Приложение A).
8. Региональный отказ оформлен как типизированная ошибка **GeoBlocked**: 403 при валидном ключе = выход из каскада без сжигания ретраев и breaker-циклов (§3.8). Подтверждённого прецедента нет — OpenRouter из РБ доступен (проверено владельцем 2026-10-20); механика остаётся общей защитой.

## 1. Проблема

Claude Pro официально недоступен в РБ из-за санкций. Нужна цепочка ИИ, работающая
в Беларуси: локальный Bionic (безлимитно, медленно) + облачные free-пулы с лимитами
и ротацией моделей + локальные роутеры. Лимиты малы (~50 req/day на провайдер),
модели ротации исчезают, параллельные запросы убивают free-тарифы и локальную VRAM.
Часть западных провайдеров (OpenAI, Anthropic) может фильтровать РБ-IP — гео-блок
обязан детектироваться явно, а не маскироваться под generic ошибку.

Вторая половина проблемы (из A1): бесплатные лимиты AI-провайдеров меняются
вендорами в произвольный момент. Если зашить числа в код или в README, они
устареют молча: приложение будет показывать «осталось 50 запросов», когда их 5,
а README будет обещать то, что вендор уже отменил. Для пользователя это выглядит
как «программа врёт». Для автора — как «баг, который не воспроизводится у меня,
потому что у меня другой аккаунт».

Самая капризная ступень цепи — free-tier OrcaRouter: суточный лимит зависит от
накопленного платежа воркспейса, free-пул моделей ротируется, а лимит размера
промпта на нижней ступени вообще не публикуется. Значит: никаких захардкоженных
лимитов; поведение при 429 и переполнении промпта определено явно; платный баланс
пользователя защищён от автоматических fallback'ов.

## 2. Решение

Каскад IAiProvider: упорядочен по DefaultPriority (меньше = раньше), липкость на
уровне ПРОВАЙДЕРА (успешный идёт первым в следующем чанке), исключение провайдера
= отказ, не крах каскада; детектор мусора TextQuality считает ответ провалом и
передаёт эстафету; липкость снимается с CoT-провайдера.

**Дефолтный каскад = облачные open-weights, доступные из РБ без VPN (локальный Bionic — опция, по умолчанию выключен):**

| Приоритет | Провайдер | Лимит/факты | Дефолт |
|---|---|---|---|
| 1  | Bionic (LM Studio, localhost:1234) | безлимитно, медленно; на CPU без GPU — 2-5 мин на CV; каталог моделей юзера — текст/кодер/OCR-vision, под задачу найдётся модель | выкл по умолчанию (галочка в настройках) |
| 10 | OpenRouter | 50 req/day free (ориентир; в коде не хранится); free-фильтр pricing.prompt=="0" && pricing.completion=="0" (СТРОКИ); openrouter/auto на free = всегда 402 (запрещён); gemma-free почти всегда 429; open-weights модели; доступен из РБ — проверено владельцем 2026-10-20 (регистрация и выпуск ключа без VPN; в ToS странового блока сервиса нет — §5.7 только про отдельные модели) | вкл |
| 20 | OrcaRouter (api.orcarouter.ai/v1, ключ sk-orca-) | лимит читается в рантайме из GET /api/free-package/public (§3); ориентир на 2026-10-18: 50/day free → ~800/day после $20 накопленных платежей воркспейса (живым чеком 2026-10-19 подтверждён: rpm 10/20); free-пул ротируется (на 2026-10-19: deepseek-v4.1-flash-free, tencent/hy4-preview-free, z-ai/glm-5.3-flash-free и др.; orcarouter/free); нужен GitHub с историей; OrcaRouter Lite (MIT) = self-host альтернатива | вкл если ключ |
| 30 | OmniRoute (локальный роутер) | мало free-моделей | вкл если настроен |
| 40 | Cherry Studio (локальный) | 2 free-модели: GLM 4.5, GLM 4.6 | вкл если настроен |
| 50 | GLM/Z.ai | ключ есть, баланса НЕТ (402/1113) → circuit breaker 10 мин держит вне цепи | слот есть, доступен по факту |

**Claude/GPT/Western-модели — opt-in с явным предупреждением в UI:** «может быть
недоступен из Беларуси — правила самих провайдеров; если получаете 403, это не
ошибка ключа».
В `keys-check` добавляется гео-пинг: если провайдер отдаёт 403 с «region restricted»
или аналогичным — причина показывается как типизированный **GeoBlocked** («недоступен
из региона»), провайдер выходит из каскада **без сжигания ретраев и breaker-циклов**;
VPN-обход не предлагается никогда — запрещён ToS самих провайдеров (§3.8).

Все провайдеры OpenAI-compatible → один тонкий LlmClient: ОДНА попытка,
типизированные ошибки (Unavailable c RetryAfter/StatusCode/BodySnapshot,
Authentication, EndpointMismatch, RequestRejected, Response, **GeoBlocked**);
классификация статусов: 408/429/5xx → Unavailable; 400/413/422 → Reject (для
OrcaRouter free 413/400 «prompt too large» = «чанк велик», см. §3.5, не «провайдер
плох»); 401/403 → Auth (403 + валидный ключ = GeoBlocked, §3.8); 404 →
EndpointMismatch; прочие 4xx консервативно Reject; caller-cancel → OCE.
Retry-цикл с backoff — собственность оркестратора ApplyPipeline, НЕ клиента.

**Потолок запросов (честно):** облачная цепь даёт сумму фактических лимитов включённых провайдеров; ориентир при OpenRouter (50) + OrcaRouter (50) = 100 req/day ≈ **5–7 полных применений /apply в день** (одно применение = 15-20 запросов: parse + eval + draft CV + draft letter + reviewer + revise + export + ATS); на одном облачном провайдере — 2-3. OpenRouter доступен из РБ — проверено владельцем 2026-10-20 (регистрация и выпуск ключа без VPN); в ToS OpenRouter странового блока сервиса нет, §5.7 запрещает только обход ограничений отдельных Model Providers на конкретные модели (Restricted Models). Больше — депозит: $10 на OpenRouter поднимает лимит free-моделей до 1000 req/day (FAQ OpenRouter, проверено 2026-10-20); ~$20 на OrcaRouter ≈ rpd 800; настроенные пользователем провайдеры или локальный Bionic. Числа читаются в рантайме (§3.1) и могут отличаться от ориентира. Bionic = безлимитно, но медленно. UI-индикатор квоты в реальном времени: «осталось X запросов сегодня из Y» (per-provider счётчики; если лимит неизвестен — так и пишется, §3.6).

Липкость по модели ВНУТРИ OpenRouter-провайдера (победитель чанка идёт первым);
сброс липкости по событию ModelBecamePaid. Кулдауны 429 персистятся в
rate-limit.json в каталоге данных приложения (`%APPDATA%\ai-job-search-by\`;
миграция из «рядом с exe» — патч 05 — RFC-006, Приложение A), адаптив 5→10→20→40→60 мин — для
прочих провайдеров и 429 без Retry-After; для free-tier OrcaRouter — фиксированный
Retry-After и один повтор (§3.3). Читаются при старте, протухшие отбрасываются;
атомарная запись живого снимка.

Профили (LlmProfileService): "me" = bionic-first цепочка выше; "public" =
cloud-only (LocalProvider отсутствует, IsAvailableAsync сам выкинет). Revision =
SHA256(name+baseUrl+apiKey-НЕ-входит) → в снапшот прогона для воспроизводимости
отклика.

Сериализация: EndpointGate (SemaphoreSlim(1)) — единственная точка HTTP к
endpoint; параллельные LLM-запросы запрещены (free-тарифы и VRAM).

Префлайт локалки: BionicPreflight ON-DEMAND (поллинг ЗАПРЕЩЁН): lms ps =
единственный источник истины о резидентных (парсинг только после шапки
IDENTIFIER, CleanCli от ANSI/спиннеров); lms load --yes = синхронный барьер
готовности; защита от задвоения моделей в VRAM. Кнопка «Тест цепочки» в
Settings = on-demand префлайт всех провайдеров с таблицей вердиктов.

Чанкование: TextChunker (EstimateTokens = байты UTF-8; required = 2*N + 2048;
границы чанков по строкам); локальный субчанк 15000 (иначе 400 Engine protocol
failed); для OrcaRouter free — урезанный бюджет субчанка (§3.5);
StripThinkingBlock перед CoT-гейтом каскада.

## 3. Механика free-tier OrcaRouter (бывший RFC-002-A1)

### 3.1 Лимиты читаются в рантайме

Лимиты бесплатных тиров читаются из публичных эндпоинтов провайдера в рантайме
и кэшируются на 30 минут. В коде и в документах конкретные числа не хранятся.

Для OrcaRouter источник — анонимный эндпоинт (без ключа):
`GET https://api.orcarouter.ai/api/free-package/public`.
Перечитывается: при старте приложения, при первом обращении к OrcaRouter в
сессии, по кнопке «Обновить квоту» в UI. Кэш 30 мин в rate-limit.json (секция
orcarouter.free-package); всё, что старше, — протухло и перечитывается.
Ориентир для README (с пометкой «числа живут в программе, не здесь»):
50/day бесплатно, ~800/day при $20+ накопленных платежей — на 2026-10-18.

### 3.2 Устройство free-tier (живой чек эндпоинта 2026-10-19)

* бесплатные лимиты опубликованы в `free_tier.tiers[]`, у каждой ступени —
  `min_paid_usd` (порог накопленного платежа), `rpm` и `rpd`. Живой чек
  2026-10-19: `$0 → rpm 10 / rpd 50`, `$20 → rpm 20 / rpd 800` — ориентир
  «50/800» подтверждён (снимок — `evidence/orcorouter-free-package-2026-10-19.json`);
* ступени разблокируются **накопленным платежом** — это не подписка, разовая
  оплата поднимает ступень навсегда;
* аккаунт, который никогда не пополнял баланс, получает намеренно маленькое
  суточное allowance;
* на нижней ступени есть **непубликуемый** лимит на размер промпта: длинный
  документ или полная история диалога в него не влезают, и он применяется
  **на каждый запрос** — ни задержка, ни уменьшение частоты его не обходят;
* окна фиксированные: поминутное и суточное (суточное сбрасывается в
  **00:00 UTC**), при исчерпании приходит `429` с заголовком `Retry-After`;
* вендор прямо предупреждает: **экспоненциальный backoff для free-уровня
  бессмысленен** — окно восполнится только на своей границе, надо ждать ровно
  `retry_after_seconds` и повторить **один раз**;
* есть именованный роутер `orcarouter/free` — один эндпоинт, роутинг по
  сложности промпта, баланс не тратится;
* структура ответа (для толерантного парсера, проверена живым чеком):
  `data.active`, `data.models[]` с `free_alias`/`base_model`/`initial_calls`/
  `daily_limit`/`minute_limit`/`is_free_tier`, у части моделей —
  `override_rpm`/`override_rpd` и собственные `tiers[]`, плюс
  `data.free_tier.tiers[]`; пул на 2026-10-19: deepseek-v4-flash-free,
  deepseek-v4.1-flash-free, orca/orcaverify-text1.0-free (5 rpm / 50 rpd),
  tencent/hy3-free, tencent/hy4-preview-free (собственные ступени
  50 rpm/250 rpd → 100 rpm/4000 rpd), z-ai/glm-5.3-flash-free;
* страховка вендора: при исчерпании free-уровня переход на платные модели
  **возвращает 429, а не списывает платный баланс** (но клиент не должен
  доводить до этого — §3.3).

### 3.3 Политика 429: следующий провайдер, платные деньги защищены

1. **429 ≠ «попробуй платный».** Каскад обязан трактовать 429 как «этот
   провайдер сейчас недоступен» и переходить к следующему в цепочке. Иначе
   приложение будет тихо тратить деньги юзера, о чём он не знает.
2. **Free-исчерпание никогда не переключает провайдера на платные модели того
   же ключа.** Клиент сам выбирает модель: при исчерпании free он обязан взять
   следующего ПРОВАЙДЕРА, а не paid-модель. Страховка вендора (429 вместо
   списания) приятна, но это не контракт. Опциональная галка «разрешить платные
   модели при исчерпании free» — по умолчанию выключена, с явным подтверждением
   трат; в v1 может быть вовсе скрыта.
3. **Backoff фиксированный, один повтор.** Если пришёл `Retry-After` /
   `retry_after_seconds` ≤ 15 мин — ждём ровно его и повторяем ОДИН раз у того
   же провайдера. Второй 429, отсутствие заголовка или пауза больше cap →
   провайдер уходит в кулдаун по общей адаптивной лестнице (5→10→20→40→60 мин)
   до границы окна, каскад идёт дальше.
4. Кулдаун персистится в rate-limit.json (§2) и не живёт зря через границу
   окна: при чтении снимка после 00:00 UTC локальный used сбрасывается (§3.4).

### 3.4 Окна фиксированные: сброс 00:00 UTC

* Суточное окно сбрасывается на стороне OrcaRouter в **00:00 UTC**. Локальный
  счётчик в rate-limit.json синхронизирован с той же точкой: снимок хранит дату
  окна (UTC); при обращении после сброса локальный used обнуляется ещё до
  ответа эндпоинта.
* Скользящее окно НЕ предполагается: 429 «за пять минут до сброса» — нормальная
  ситуация. UI показывает «до сброса квоты: Xч Yмин (00:00 UTC)».
* Поминутное окно (rpm) обрабатывается тем же фиксированным Retry-After
  (обычно секунды), без адаптивной лестницы.

### 3.5 Непубликуемый лимит промпта: сокращать заранее

Лимит размера промпта на нижней ступени нельзя узнать из API, поэтому длинный
вход измеряется и сокращается ЗАРАНЕЕ, а не упирается в отказ:

* субчанк-бюджет для OrcaRouter free: константа `orcaFreeSubchunkTokens`,
  стартово **10 000** токенов (против локальных 15 000; уточняется живым тестом
  при интеграции — реестр «НЕ ЗНАЮ»);
* резюме обрезается до релевантного (по опыту/навыкам вакансии) до отправки —
  полная история диалога и полный текст CV на эту ступень не уходят;
* если всё же пришёл 413/400 «prompt too large» — оркестратор делит чанк
  пополам и делает **ОДИН** ретрай у того же провайдера (Reject здесь означает
  «чанк велик», а не «провайдер плох»); второй отказ = провайдер пропускается
  для этого чанка, каскад идёт дальше.

### 3.6 Толерантный парсинг и дисциплина чисел

* Структура ответа free-package может измениться (ротация пула, смена API,
  Cloudflare-заглушка). Парсер терпим: нераспознанная форма → состояние
  **«лимит неизвестен»** (UI: «OrcaRouter: лимит неизвестен»), не падение и
  НЕ «0 осталось» — ноль выглядит как исчерпанная квота и пугает зря.
* Частичный ответ (есть used, нет limit) = «осталось неизвестно».
* Числа живут в трёх местах: рантайм-эндпоинт (источник), rate-limit.json
  (снимок), UI (отображение). В README и в генерируемых таблицах
  (AI_PROVIDER_TABLE) жёстко вбитых 50/800 нет — только «лимит читается
  программой при запуске».

### 3.7 Ступень по накопленному платежу

Для аккаунта без оплаты берётся нижняя ступень (консервативная оценка квоты).
Опциональное поле «накопленный платёж воркспейса» в настройках повышает
точность счётчика; при расхождении с эндпоинтом приоритет у эндпоинта.

### 3.8 Гео-блок — отдельный исход

403 при валидном ключе трактуется как **GeoBlocked** «провайдер недоступен из
региона»: явная пометка в интерфейсе, выход из каскада БЕЗ сжигания ретраев и
breaker-циклов. Обход VPN не предлагается никогда — он запрещён ToS самих
провайдеров (для OpenRouter — §5.7 ToS). Подтверждённого прецедента нет:
OpenRouter из РБ доступен (проверено владельцем 2026-10-20 — регистрация и
выпуск ключа без VPN); механика остаётся общей защитой на случай региональных
ограничений у любых провайдеров и моделей.

## 4. Альтернативы (почему нет)

- Один провайдер: ротация free-моделей и санкции ломают single-point. ОТКЛОНЕНО.
- Параллельный обход провайдеров: убивает free-лимиты и локальную VRAM
  (гонка вытеснения → 400 Engine protocol failed). ОТКЛОНЕНО.
- Поллинг-watchdog в UI-цикле: on-demand достаточен для прогона по требованию,
  поллинг только опционально в UI-режиме, не в v1. ОТКЛОНЕНО.
- Claude/GPT в дефолтной цепи: гео-блок РБ, ключ может быть валидным но 403
  приходит на ровном месте. ОТКЛОНЕНО для дефолта, оставлено как opt-in.
- Хардкод лимитов free-тиров в коде/README: устареют молча — «программа врёт»,
  невоспроизводимые «баги» из-за разных аккаунтов. ОТКЛОНЕНО (§3.1).
- Экспоненциальный backoff на free-уровне OrcaRouter: окно всё равно
  восполнится только на границе, экспонента лишь жжёт попытки. ОТКЛОНЕНО —
  фиксированный Retry-After, один повтор (§3.3).
- Авто-fallback на платные модели того же ключа при исчерпании free: тихо
  тратит деньги юзера. ОТКЛОНЕНО — только opt-in галкой с подтверждением (§3.3).
- Зондирование непубликуемого лимита промпта пробными запросами: жжёт квоту и
  хрупко. ОТКЛОНЕНО — упреждающий субчанк + один ретрай 413 пополам (§3.5).

## 5. Последствия и честные ограничения

- Публичная цепь без локалки = 100 req/day ≈ 5-7 применений /apply в день (на одном облачном провайдере — 2-3)
  (ориентир). README говорит это прямо; не обещать «массовый поиск».
- Ротация free-пулов: провайдер с протухшим пулом выпадает каскадом, не крашит.
- Bionic первым = медленно на длинных пайплайнах; липкость держит стиль внутри
  прогона; UI предупреждение «на CPU без GPU — 2-5 минут на CV».
- GLM/ZCode: баланса нет — не предлагать «просто использовать GLM»; ZCode
  припаркован (триггер — появление баланса).
- OmniRoute/Cherry Studio: контракты OpenAI-compatible, конфигурация в
  local.json; документация провайдеров — из настроек владельца (OmniRoute —
  profile: me, в публичных таблицах README не публикуется).
- **Санкционный контекст:** прямые ключи Claude/GPT/Western-моделей могут не
  работать из РБ (правила самих провайдеров); дефолтный каскад состоит только
  из open-weights (DeepSeek, Qwen, GLM и т.п.); западные модели — opt-in с
  предупреждением о возможных региональных ограничениях. OpenRouter из РБ
  доступен — проверено владельцем 2026-10-20.
- «Лимит неизвестен» — штатный режим, не ошибка: эндпоинт недоступен или
  изменился → каскад продолжает работать на общих кулдаунах, UI пишет честно.
- Субчанк OrcaRouter free мельче локального → длинные CV на этой ступени идут
  бОльшим числом запросов и исчерпают её раньше; осознанный компромисс против 413.
- Ориентир «50/800» устареет рано или поздно — и это нормально: единственный
  источник — рантайм; README не обещает числа.
- Страховка вендора «429 вместо списания платного баланса» не входит в контракт
  клиента — на неё не полагаемся (§3.3).

## 6. Константы (переносимые из проверенной инфраструктуры)

Тик watchdog-механики 5 с; попыток автозагрузки 3; пауза между циклами 60 с;
кулдаун 429 старт 5 мин адаптив до 60; breaker GLM 10 мин; SystemReserve 2048;
локальный субчанк 15000; чанк под GLM 60000; HTTP-таймаут облако 240 с;

2. Решение
2.1 Контракт и базовые классы

IPortalService (search/detail → нормализованные вакансии, формат json)

    ЧЕТЫРЕ базовых класса по типу доступа:

    ApiPortalBase — официальный JSON API (HttpClient + парсинг);
    FeedPortalBase — RSS/Atom (XmlReader + Markdig для описаний);
    ScrapePortalBase — HTML: polite-crawl (паузы между запросами,рандомизация задержек, уважение robots.txt и X-RateLimit/Retry-After,инкрементальный since, лимит страниц за прогон) + per-portal breaker;
    GovernmentPortalBase (WP-P7) — строгий polite-crawl + дисклеймер«официальный источник, данные сверять с первоисточником».

Каждый адаптер несёт HealthCheckAsync() — канареечный запрос сgolden-фикстурой (записанный HTML-snippet ожидаемой структуры). Провал →PortalHealthStatus.Degraded в UI с бейджем «портал сломан, обновлениеожидается» + per-portal kill-switch (чекбокс «отключить до фикса»).Adapter Doctor (кнопка в Settings) — прогон всех health-check, таблицавердиктов.

Раскладка ядра v1 по классам: remoteok/remotive/jobicy — ApiPortalBase;wwr/nodesk/himalayas — FeedPortalBase; hirify (WP-P4) — ApiPortalBase с личным ключом пользователя.

2.9 keys-check (on-demand, без поллинга)

    auth=none → зелёный сразу;
    personal_key/public_key (hirify, adzuna, jooble, careerjet,web3_jobs) → наличие в config/local.json + живой минимальный пинг(per_page=1 и т.п.);
    отсутствующий ключ = портал ВЫПАЛ из цепи С ПРИЧИНОЙ в отчёте, не краш;
    старт без ключей = работаем на 7 enabled auth=none (коробка из zip ищетсразу; hirify — ручное включение после ввода ключа);
    гео-пинг: 403 с «region restricted» или аналогичным → типизированнаяошибка GeoBlocked (RFC-002 §3.8): причина в UI, не generic ошибка, безсжигания ретраев.

2.10 Backoff и breaker

Консервативный backoff по умолчанию (лимиты почти везде неизвестны):пауза между запросами + экспоненциальный backoff на 429/503 + персисткулдауна в %APPDATA%\ai-job-search-by\rate-limit.json (патч 05, миграцияиз «рядом с exe»; лестница согласована с RFC-002: старт 5 мин, адаптив до60). Scrape-порталы: авто-выключение после N подряд падений парсинга(breaker) + golden-фикстуры разметки в тестах (сайт сменил вёрстку =красный тест, не сюрприз у юзера).

# RFC-004 — Ключи, гигиена репозитория и keys-check

Статус: proposed | Дата: 2026-10-18 | Рев. 2026-10-19: сверка с патчем 05 (%APPDATA%), RFC-002 §3.8 (GeoBlocked), RFC-003 §2.3/§2.9 (7 порталов, keys-check) и стеком RFC-001 | Слит в DECISIONS.md: 2026-10-20 (3), решение владельца | Владелец: ThreeI
Scope: корень репозитория

## 0. Что изменилось в рев. 2026-10-19

1. «Старт без ключей = 8 enabled auth=none» → **6** (международные фиды; hh и rabota_by выбыли по проверенным основаниям — RFC-003 §2.3; единственный проверенный РБ-источник исключён владельцем 2026-10-20 — RFC-008).
2. Пути приведены к патчу 05: весь персист — в `%APPDATA%\ai-job-search-by\`,
   не «рядом с exe» (установка в Program Files не должна ломать запись).
   Канон патча 05 уточнён по ролям файлов: `settings.json` (без секретов)
   + `local.json` (только секреты).
3. Гео-блок — типизированная ошибка `GeoBlocked` (RFC-002 §3.8) в ОБОИХ
   контурах: префлайт AI-провайдеров и keys-check порталов; без сжигания
   ретраев.
4. THIRD-PARTY-NOTICES синхронизирован со стеком RFC-001; QuestPDF —
   Community License v3.0 (не OSI-OSS), лицензия проверяется при старте
   (патч 01).
5. Security-гард переформулирован как CI-джоб на каждый PR (блокирует
   merge): xUnit в CI не видит staged-файлы.
6. `.gitignore` дополнен `*.db-shm`/`*.db-wal`; legacy-пути
   (`config/local.json`, `data/`, `logs/`) оставлены в gitignore как

7. Опечатка `toS_status` → `tos_status`; поля `tos_status`/`lastTermsCheck`/
   `tos_evidence` живут в реестре `config/registry.json` (schema v3),
   каталог лишь отображает карточки.

## 1. Проблема

Публичный продукт + персональные ключи (AI-провайдеры, порталы с
personal_key) и личные данные (CV, профиль, история откликов).
Upstream-оригинал писал профиль в tracked-файлы (/setup) — для публичного
форка это раздача своего CV миру. Юзер может по ошибке положить ключ в
отслеживаемый app.json. Гео-блоки реальны с обеих сторон цепочки:
AI-провайдеры (региональные ограничения у части провайдеров и моделей —
механика RFC-002 §3.8; OpenRouter из РБ доступен — проверено владельцем
2026-10-20) и порталы (403 «region restricted» для РБ-IP). Без детекции это выглядит
как «неверный ключ» и заводит юзера в тупик пересоздания ключей.

## 2. Решение

### 2.1 Послойный конфиг и канон путей

Слои: код-дефолты ← `config/app.json` (tracked, в репо, без секретов,
read-only в рантайме) ← `%APPDATA%\ai-job-search-by\local.json` (вне репо,
создаётся при вводе первого ключа).

Канон путей (патч 05, роли файлов уточнены настоящим RFC):

```
%APPDATA%\ai-job-search-by\
├── settings.json     — UI-настройки, порядок/чекбоксы порталов (БЕЗ секретов)
├── local.json        — ТОЛЬКО секреты: Ai.* (RFC-002), Portals.{id}.* (RFC-003)
├── rate-limit.json   — кулдауны (единая лестница RFC-002/003)
├── jobs.db           — SQLite: вакансии, дедуп, история откликов
├── documents\        — сгенерированные CV/письма
└── logs\
```

`local.json` отделён от `settings.json` сознательно: файл настроек можно
приложить к баг-репорту, файл ключей — никогда. Секции ключей: `Ai.*`
(провайдеры, RFC-002) и `Portals.{id}.*` (`ApiKey`/`AppId`/`AppKey`/
`ClientId`/`ClientSecret`, счётчик jooble «осталось N из 500»).
Атомарная запись, снапшот на прогон + хэш в отчёт.
`ConfigService.Validate`: попытка записать ключеобразное значение
(`sk-*`, `Bearer`, `app_key`, `client_secret`) в `app.json` ИЛИ
`settings.json` = `ConfigValidationException`, ключ не сохраняется, юзер
видит причину.

### 2.2 UI-гигиена ключей

- Ключи замаскированы (`PasswordChar`) во всех полях настроек.
- «Тест цепочки» — on-demand префлайт AI-провайдеров (RFC-002);
  403 при валидном ключе = вердикт «гео-блок», не «неверный ключ»
  (типизированный `GeoBlocked`, RFC-002 §3.8, без сжигания ретраев).
- «keys-check» порталов (RFC-003 §2.9): `auth=none` → зелёный сразу;
  ключевой портал → наличие в `local.json` + живой минимальный пинг
  (per_page=1); 403 с «region restricted» → вердикт «портал недоступен
  из Беларуси» (`GeoBlocked`); нет ключа или пинг мёртв → портал ВЫПАЛ
  из цепи С ПРИЧИНОЙ в отчёте, не краш.
- Старт без ключей = работаем на **6 enabled auth=none** (RFC-003 §2.3: международные фиды; RFC-008); hirify — ручное включение после ввода ключа («есть ключ — есть источник»).

### 2.3 Личные данные

Профиль/CV/история откликов — только в `%APPDATA%\ai-job-search-by\`
(`jobs.db`, `documents\`, `logs\`): в папке репозитория и рядом с exe
личных данных нет вообще. Онбординг (аналог /setup) физически не умеет
писать вне белого списка: xUnit-гард проверяет пути записи онбординга
против `%APPDATA%\ai-job-search-by\**`.

- Uninstall-инструкция в README (+ troubleshooting, патч 05): удалить
  папку программы + `%APPDATA%\ai-job-search-by\` — машина чистая.

### 2.4 Юридический и privacy-щит

- `DISCLAIMER.md` в корне репо: инструмент не аффилирован с порталами;
  юзер использует на свой риск; мы уважаем robots.txt и ToS; если портал
  пришлёт претензию — адаптер уходит в graveyard реестра с цитатой
  (практика RFC-003 §2.13).
- `PRIVACY.md`: что уходит в облако AI-провайдеров (текст CV и вакансии —
  только по явному действию юзера; профили me/public — RFC-002), что
  остаётся локально (`%APPDATA%\ai-job-search-by\`), как удалить всё
  полностью.
- `SECURITY.md`: как сообщить об уязвимости (email/приватный контакт,
  не публичный GitHub issue), политика раскрытия.
- `THIRD-PARTY-NOTICES.md` — по стеку RFC-001: Avalonia 12.1.1 (MIT),
  CommunityToolkit.Mvvm 8.4.2 (MIT), Microsoft.Data.Sqlite 10.0.10 (MIT),
  Dapper 2.1.79 (Apache-2.0), Markdig 1.3.2 (BSD-2-Clause),
  DocumentFormat.OpenXml 3.2.0 (MIT), UglyToad.PdfPig (Apache-2.0),
  QuestPDF 2026.8.0 —
  **Community License v3.0, не OSI-OSS** (бесплатно физлицам и
  организациям <$1M; госорганы/публичные компании — not eligible
  regardless of revenue; `QuestPDF.Settings.License` при старте — патч 01).
- Комплект щитов (`DISCLAIMER.md` + `PRIVACY.md` + `SECURITY.md` +
  `THIRD-PARTY-NOTICES.md`) обязателен в корне репо И в zip; без него
  релиз не публикуется (релиз-чеклист).

### 2.5 Гигиена репозитория (с commit 0)

`.gitignore` (defense-in-depth: рантайм-пути вне репо по патчу 05, но
страховка от старых привычек и инструментов):

- `config/local.json` (legacy-путь ключей),
- `data/`, `logs/`, `*.db`, `*.db-shm`, `*.db-wal` (личные данные, БД и
  WAL-сателлиты),
- `bench/` артефакты (результаты прогона, фикстуры с копирайтом),
- `*.user` (локальные override-конфиги IDE).

Security-гард (CI-джоб, на каждый PR): сканирует файлы диффа PR на
ключеобразные паттерны (`sk-*`, `Bearer `, `password = "`,
`client_secret`) и личные данные (email-паттерны + ФИО-паттерны в
`*.json`/`*.md` вне `PRIVACY.md`); находка блокирует merge с понятным
сообщением.

## 3. Альтернативы (почему нет)

- ОС-секретницы (DPAPI/keyring): кроссплатформенная боль и нечитаемость
  из консоли/FAR-воркфлоу владельца; локальный файл проще и честнее для
  v1. **Опция v2**: DPAPI-шифрование ключей в `local.json` для Windows
  (прозрачное, без изменения UX).
- Env-переменные как основной механизм: неудобно GUI-юзеру публики;
  разрешены только как опциональный override поверх `local.json`
  (CI/серверные сценарии v2).
- Один общий файл настроек с секретами (секретные секции прямо в
  `settings.json`): убивает безопасный сценарий «приложи конфиг к
  баг-репорту»; разделение settings/local дешевле DPAPI и закрывает
  главный бытовой сценарий утечки. ОТКЛОНЕНО.

## 4. Последствия

# RFC-005 — Экспорт CV/cover letter и ATS-чек без LaTeX

Статус: proposed | Дата: 2026-10-18 | Рев. 2026-10-19: сверка с патчем 01 (шрифты/лицензия), патчем 05 (%APPDATA%), RFC-001 (версии/тесты) и RFC-004 (NOTICE, пути); Markdig возвращён к BSD-2-Clause (сверка по NuGet, RFC-007) | Слит в DECISIONS.md: 2026-10-20 (3), решение владельца | Владелец: ThreeI
Scope: корень репозитория

## 0. Что изменилось в рев. 2026-10-19

1. **Шрифтовый тезис переписан по патчу 01**: «дефолтные шрифты QuestPDF
   не содержат кириллицу» — ошибка; Lato 2.015 (SIL OFL 1.1) встроен в
   QuestPDF и кириллицу покрывает. Дефолт = Lato, ничего бандлить в v1
   не нужно (DejaVu/Noto из черновика исключены). Настоящий киллер —
   системные имена шрифтов в коде экспортёров: железный запрет + аудит
   до порта + тест на чистом CI-runner без Arial.
2. Glyph-coverage проверка перед рендером ОСТАЁТСЯ как защита от
   эмодзи/CJK в текстах вакансий: ясная ошибка со списком недостающих
   символов, не молчаливые квадраты. Noto-fallback — опция v1.1
   (патч 01 §2.3), в v1 не возим.
3. `NOTICE.md` → `THIRD-PARTY-NOTICES.md` (единое имя по RFC-004).
   Markdig — **BSD-2-Clause**: правка «BSD-2 → MIT (как в RFC-001/004)»
   в этой ревизии была ошибкой — она перенесла неверную запись из
   RFC-004 §2.4 (в RFC-001 лицензия Markdig не указана вовсе); сверено
   по NuGet/deps.dev 2026-10-19: xoofx/markdig, BSD-2-Clause (RFC-007 §2.4).
4. QuestPDF-лицензия выставляется **при старте приложения, до первого
   рендера** (патч 01 §2.2), а не «PdfExporter пишет идемпотентно»;
   тест ассертит порядок.
5. Пути экспорта → `%APPDATA%\ai-job-search-by\documents\` (патч 05,
   RFC-004 §2.1); формулировка «data/ под gitignore» устарела.
6. Ссылка на `architecture.md §3.5` ведёт к документу в корне репозитория
   (раздел 3.5 «Экспорт», RFC-001 §5). Контракт IFormatExporter
   принадлежит настоящему RFC.
7. «Опциональные OFL-семейства (Lato/Raleway)» переформулированы: Lato —
   уже встроенный дефолт; ЛЮБОЕ стороннее семейство = исключение — файлы
   шрифта в приложении + текст лицензии (OFL.txt), никогда из системы;
   папка upstream OpenFonts не копируется (в ней нет лицензионного текста).

## 1. Проблема

Upstream компилирует CV/письмо через LaTeX (lualatex/xelatex,
MiKTeX/TeX Live): гигабайты, CTAN-автоустановки, GUI-попапы, ломающие
CLI-автоматизацию. На слабом ноутбуке публики это непроходимо. При этом
требования оригинала сохраняем: CV = ровно 2 страницы, письмо = 1 страница
с видимой подписью, ATS-проверка text-слоя (контакты литерально, порядок
чтения, покрытие ключей).

Второй класс рисков — шрифты, и он НЕ там, где казалось. Кириллица в
QuestPDF работает из коробки (Lato встроен). Реальные ловушки: (а)
системное имя шрифта в коде экспортёра — у юзера без этого шрифта экспорт
падает исключением «font family not found», у автора на машине баг не
воспроизводится (патч 01 §1.2); (б) молчаливые квадраты на символах вне
покрытия шрифта (эмодзи, CJK из названий вакансий). Обе ловушки
закрываются правилами и тестами настоящего RFC, а не выбором шрифта.

## 2. Решение

Markdown → PDF (QuestPDF 2026.8.0) / DOCX (DocumentFormat.OpenXml 3.2.0) /
HTML (Markdig 1.3.2) через контракт `IFormatExporter`; регистрация нового
формата = одна реализация интерфейса (аналог /add-template). Контракт
и экспорт-пайплайн определены здесь (архитектурного документа нет —
RFC-001 §5). Перед экспортом markdown проходит детерминированную
пост-обработку LLM-черновика (PostProcessor: strip ```-фенсов —
ступень между revise и export).

- **Шрифты (патч 01):** дефолт = Lato (встроен в QuestPDF, кириллица из
  коробки), константа `PdfFonts.Base = "Lato"`; все FontFamily — только
  через константы экспортёра. ЖЕЛЕЗНЫЙ ЗАПРЕТ системных имён
  (Arial/Calibri/Segoe UI/Times New Roman/Tahoma/Verdana) в коде
  экспортёров; аудит перед портом (rg-паттерн патча 01 §2.1, особое
  внимание константе `ExportStyles` — порт 1:1, проверять на
  системные имена); `UseSystemFonts = false` не меняем. Стороннее
  семейство = исключение: файлы в приложении + текст лицензии (OFL.txt),
  никогда из системы; upstream OpenFonts не копируется.
- **Glyph-coverage перед рендером:** символы текста вне покрытия
  выбранного шрифта → ясная ошибка со списком недостающих символов, НЕ
  молчаливые квадраты. Noto-fallback (эмодзи/CJK) — опция v1.1 по
  патчу 01 §2.3 (FontDiscoveryPath / RegisterFontsFromDirectory).
- **Шаблоны CV/письма** = Markdown-шаблоны в `prompts/templates/`
  (структура секций и правила tailoring портированы чтением upstream
  `cv/main_example.tex` и `cover_letters/cover.cls` как РЕФЕРЕНСА, байты
  не копируем).
- **Page-count:** после рендера PdfPig читает число страниц и text-слой.
  CV ≠ 2 стр или письмо ≠ 1 стр → детерминированные шаги ужатия
  (шаг кегля → шаг интервалов → перенос блока), ре-рендер, максимум
  2 итерации; не влезло → warning юзеру с фактом «N страниц», НЕ
  молчаливый выход.
- **ATS-чек = детерминированные правила (без LLM):** контакты присутствуют
  в text-слое литерально; нет мусорных маркеров и thinking-блоков
  (детектор мусора/цензуры); покрытие ключей вакансии против профиля =
  скор в отчёте (ключи, которые профиль реально поддерживает, добавляются;
  дыры остаются видимыми, keyword stuffing запрещён); числа/даты
  консистентны с профилем (жадные regex-классы заканчивать цифрой:
  «[\d.-]+» съедает хвостовую точку — выстраданное правило).
- **Лицензия (патч 01 §2.2):** `QuestPDF.Settings.License =
  LicenseType.Community` выставляется при старте приложения, до первого
  `Document.Create`, один раз.

## 3. Альтернативы (почему нет)

- LaTeX опционально для power-users: вес установки и поддержка двух путей
  рендера; триггер возврата — явный запрос сообщества. ОТКЛОНЕНО для v1.
- Typst: ещё один рантайм-бинарник; QuestPDF уже проверен на живых
  файлах. ОТКЛОНЕНО.
- Бандл DejaVu Sans/Noto Sans как дефолт (черновик): Lato уже внутри
  QuestPDF — бандл растит артефакт без пользы; Noto — только как
  fallback-опция v1.1 по патчу 01 §2.3. ОТКЛОНЕНО.

## 1. Проблема

Публика = слабые ноутбуки без GPU, без платного Claude, часто под
региональными ограничениями платных AI-сервисов. Установка обязана быть
«распаковал и ищет», без Python/Node/LaTeX/регистраций на старте. При
этом нельзя обещать того, чего free-цепочка физически не тянет.
Дополнительные блокеры диспута: неподписанный exe = SmartScreen «Windows
защитила ваш компьютер» у большинства юзеров до первого запуска (оценка
диспута 70–80%); README, продающий «N порталов», проигрывает браузеру по
скорости и доверию — killer-feature (tailored-отклик за минуты) обязан
быть первым экраном, а не счётчик источников.

## 2. Решение

### 2.1 Сборка и zip

- `dotnet publish -c Release -r win-x64 --self-contained` → папка → zip.
  Single-file опционален позже; папка-zip надёжнее с Avalonia native-либами
  и даёт меньше AV-ложных срабатываний (RFC-001 §4).
- Внутри zip: exe-папка + README.txt + LICENSE + LICENSE-THREEI.md +
  licenses\ (ThirdPartyNotices-dotnet.txt, LATO-OFL.txt — RFC-007 §2.5) +
  DISCLAIMER.md + TROUBLESHOOTING.md + THIRD-PARTY-NOTICES.md +
  PRIVACY.md + SECURITY.md (чеклист п.10, RFC-004 §2.4). Настройки,
  ключи и данные создаются при
  первом старте в `%APPDATA%\ai-job-search-by\` (патч 05, RFC-004) —
  ключей и личных данных в zip нет по построению.
- SHA256-чексуммы zip в release notes + GPG-подпись релиза (опционально).
- Код-подпись: решение «не подписывать в v1» (патч 05 §1). В README
  честно: предупреждение SmartScreen — постоянная часть первого запуска
  неподписанного open-source; репутация набирается скачиваниями и
  winget-сабмитом, не в день 1.
- Пробный workflow GitHub Actions из белорусского аккаунта — зафиксировать
  результат до релиза (чеклист п.10).

### 2.2 Первый запуск на Windows (SmartScreen-workaround, патч 05)

- Порядок в гайде: снять Mark of the Web с **zip до распаковки**
  (свойства zip → «Разблокировать») — у файлов из архива пометка
  наследуется, снимаем с zip → вся папка чистая; если распаковали раньше —
  свойства exe → «Разблокировать».
- SmartScreen: «Подробнее» → «Выполнить в любом случае». Раздел «Первый
  запуск на Windows» в README.txt и README.md — СО СКРИНШОТАМИ
  (чеклист п.3).
- Никогда не советовать отключать SmartScreen целиком (патч 05 п.1.4);
  если антивирус удалил/карантинит файл — сценарий «AV-карантин» в
  troubleshooting, а не советы по исключениям Defender.
- НЕ обещать «двойной клик и работает»: честная формулировка «первый
  запуск потребует одного подтверждения SmartScreen — это нормально для
  неподписанного open-source».
- Roadmap: winget-сабмит (бесплатно, review, накапливает репутацию и
  снижает частоту предупреждений — патч 05, чеклист «желательно»).

### 2.3 Профили me/public

- Дефолтный профиль «public»: free-цепочка RFC-002 §2 — OpenRouter free
  (ориентир 50/day; доступен из РБ — проверено владельцем 2026-10-20) → OrcaRouter free (лимит
  читается в рантайме из free-package, RFC-002 §3). Bionic/LocalProvider
  в public-профиле отсутствует — IsAvailableAsync сам выкинет локалку из
  цепи. OmniRoute — личная инфраструктура владельца (profile: me), в
  публичные таблицы и дистрибутив не попадает.
- Профиль «me» владельца = bionic-first; в дистрибутив не входит,
  документирован как опция для владельцев GPU.
- Bionic по умолчанию ВЫКЛЮЧЕН — галочка в настройках снята (решение
  владельца 2026-10-20, рев. 7): локальная ступень — opt-in.
  Включённый Bionic = ступень №1 (безлимитно, медленно). Каталог
  моделей пользователя (текст/кодер/OCR-vision) покрывает задачи цепи;
  советовать LM Studio людям — после релиза (PLAN §9).

### 2.4 Коробка ищет без единого ключа

- Ядро v1 (RFC-003 §2.3): **6 порталов enabled auth=none** — remoteok, remotive, jobicy (official API), wwr, himalayas, nodesk (RSS/feed).
- hh и rabota_by выбыли по проверенным основаниям — UI объясняет причину,
  если пользователь спросит «где hh» (RFC-003 §4).
- Ключевые источники (hirify и backlog) подключаются через keys-check +
  «Каталог регистраций» (portals-catalog.md → раздел README):
  пошагово «куда идти, где генерить ключ, в какую секцию
  `%APPDATA%\ai-job-search-by\local.json` класть» (RFC-004 §2.1).
- Нет ключа = компонент вне цепи С ПРИЧИНОЙ в отчёте, не краш
  (RFC-003 §2.9 / RFC-004 §2.2).

### 2.5 Позиционирование README (killer-feature первым экраном)

- Hero: «Персонализированный отклик за 5 минут: CV + cover letter +
  ATS-чек, локально, бесплатно, без подписки» — НЕ «агрегатор N порталов».
- Сценарий первым блоком: вставил CV → выбрал направление → получил
  короткий список релевантных вакансий и готовые черновики откликов.
- Таблица сравнения (обязательна, иначе первый же комментарий сделает её
  за нас и злее): vs upstream ai-job-search (нужен Claude Pro + LaTeX +
  терминал); vs career-ops (агент внутри подписочного AI-CLI); vs jobspy
  (нужен Python); vs SaaS (LoopCV/Simplify — платно, облако, данные
  наружу). Сравнение публикуем ТОЛЬКО по пунктам, реально реализованным
  в v1.
- Честные лимиты: облачный ориентир 50 (OpenRouter) + 50 (OrcaRouter) = 100 req/day ≈ **5–7 полных применений /apply в день** (одно применение = 15–20 запросов; RFC-002 §2, рев. 2026-10-20; на одном облачном провайдере — 2–3). Числа не хардкодятся: per-provider счётчики читаются в рантайме, UI-индикатор квоты реального времени («осталось X запросов сегодня из Y»; «лимит неизвестен» — так и пишется, RFC-002 §3.6). Bionic = безлимитно, но медленно и нужна GPU (в public-профиле отсутствует; по умолчанию выключен — галочка в настройках, рев. 2026-10-20).
- Секция «Санкционный контекст РБ» — честно (рев. 2026-10-20): OpenRouter из
  РБ доступен — проверено владельцем (регистрация и выпуск ключа без VPN);
  в ToS странового блока сервиса нет (§5.7 — только ограничения отдельных
  моделей); гео-пинг при первом старте остаётся общей защитой
  (`GeoBlocked` — типизированная ошибка, RFC-002 §3.8); Restricted Models
  (Claude/GPT-класс) в free-пуле недоступны; оплата подписок из РБ
  ограничена; LinkedIn недоступен у части РБ-провайдеров. Без нытья:
  «недоступно → free-цепочка и локальные опции».
- QuestPDF Community-строка + ссылка на лицензию (патч 01; Lato встроен —
  кириллица работает в первый день); MIT-атрибуция upstream (RFC-007);
  телеметрии нет, данные локально (`%APPDATA%\ai-job-search-by\jobs.db` —
  патч 05); PRIVACY.md ссылкой из README.

### 2.6 Релизные документы (гейт: без них тег не ставится)

- `troubleshooting.md` — уже в пакете; минимум 10 сценариев с точными
  сообщениями: SmartScreen, 429/квота, «портал вернул 0 вакансий»,
  Cloudflare/капча, PDF (исключение «font family not found» = системное

- `MAINTENANCE.md` (корень, готовится) — политика сопровождения и публичный

  known-issues.md и portals-health.md — RFC-003 §5): core-адаптеры чинятся
  в первую очередь; experimental могут ждать; адаптер сломан >30 дней =
  deprecated в README; бейдж «maintenance mode» при low-energy режиме
  автора.
- Релиз-гейт — PLAN.md §8 (отдельный RELEASE.md НЕ создаём): чексуммы,

- Журнал PLAN.md §12 + SemVer: фикс адаптера = patch, новый портал/фича =

- CI: `.github/workflows/ci.yml` — smoke-build на каждый PR и тег;

## 3. Альтернативы (почему нет)

- Инсталлятор (Inno/MSIX): подпись кода не решает SmartScreen (патч 05),
  AV-фолспозитивы остаются в любом виде; zip + README.txt проще и честнее.
  ОТКЛОНЕНО для v1.
- Framework-dependent сборка (меньше вес): требует .NET-рантайм на чужом
  ноуте = «скачай ещё что-то» = смерть конверсии. ОТКЛОНЕНО: только
  self-contained.
- Single-file exe дефолтом: Avalonia native-либы + AV-эвристики на
  single-file .NET = больше ложных срабатываний. ОТКЛОНЕНО для v1.

## 4. Последствия

- Вес zip — ориентир 100–200 МБ (self-contained); фактический размер
  фиксируется в CHANGELOG, до publish в README размер не обещается
  (чеклист п.10).
- AV/SmartScreen-трение принято как данность с гайдом и скриншотами;
  репутация набирается скачиваниями и winget-сабмитом, не в день 1
  (патч 05).
- Публичная цепь и цепь владельца = один код, два профиля конфигов;
  расхождения только в конфиг-слое, не в коде (RFC-002/004); OmniRoute
  не попадает в публичные артефакты.
- Релиз-гейт: тег не ставится без зелёного CI (build + docs-consistency),
  заполненного гейта PLAN.md §8 и обновлённого журнала PLAN.md §12.
- Соло-мейнтейнер защищён от выгорания политикой MAINTENANCE.md: ожидания
  по срокам ответов на issues заявлены честно («ответа может не быть
  неделями»), адаптеры experimental = community-maintained.

# Приложение A — Поглощённый патч 05: SmartScreen и путь конфигурации

**Статус:** принят 2026-10-19, поглощён в RFC-006 как приложение | **Происхождение:** бывший `docs/patches/05-smartscreen-and-config-path.md` (каталог patches/ удалён при переходе к дереву репозитория); тело ниже дословно.

## 1. Подпись кода: решение — не подписывать в v1

Проверка вариантов (2026):

| Вариант | Вердикт |
|---|---|
| EV-сертификат | Не решает: с 2024 SmartScreen опирается на накопленную репутацию файла, а не на тип сертификата. Стоимость — тысячи долларов в год |
| OV-сертификат (Certum и др.) | $150–300/год; предупреждение SmartScreen всё равно показывает, пока не накопится репутация. «Купил и забыл» — не работает |
| Azure Trusted Signing | Физлицам доступна только в США и Канаде; для автора из РБ закрыта (и по географии, и по оплате) |
| Ничего + документация | Принято. Предупреждение SmartScreen — постоянная часть первого запуска, обход documented, а не разовый хак |

Следствия:

1. Раздел SmartScreen в troubleshooting и в README — **обязательный**
   (релиз-чеклист, п. 3), со скриншотами.
2. В гайде обязательно описан сценарий **снятия Mark of the Web с zip до
   распаковки**: иначе пользователь, распаковавший первым, не найдёт галочку
   «Разблокировать» у exe (у файлов из архива пометка наследуется от zip;
   снимаем с zip — вся папка чистая).
3. `winget`-манифест — желательный пункт чеклиста: публикации через winget
   накапливают репутацию и постепенно снижают частоту предупреждений.
4. Никогда не советовать пользователю отключать SmartScreen целиком.

## 2. Путь данных: %APPDATA%, не рядом с exe

Канон:

```
%APPDATA%\ai-job-search-by\
├── settings.json
├── rate-limit.json
├── jobs.db
└── logs\
```

Мотивация: установка в `Program Files` (или любая папка без прав на запись)
не должна ломать программу. Паттерн «кулдауны рядом с exe» в
этом виде **не портировать**.

Миграция с ранних сборок: при старте, если `%APPDATA%\ai-job-search-by\`
пуст, а рядом с exe найден `rate-limit.json` (или `settings.json`) —
перенести файлы в `%APPDATA%` и залогировать перенос. Старые файлы не
удалять (переименовать в `*.migrated`).

Проверки (релиз-чеклист, п. 3):

* запуск из `Program Files` не падает — данные всё равно пишутся в `%APPDATA%`,
  а README по-прежнему советует не держать там установку;
* кириллическое имя пользователя Windows (путь `%APPDATA%` содержит
  кириллицу) — прогон smoke-теста;
* деинсталляция: удаление папки с программой + `%APPDATA%\ai-job-search-by\`
  оставляет машину чистой (описано в troubleshooting).

## 1. Проблема

Мы берём из upstream (MIT): LICENSE-обязанность, идеи контрактов
порталов и тестов, референс воркфлоу. Markdown-промпты/команды/скиллы
upstream НЕ переносятся (решение владельца 2026-10-20, §2.2).
Публичный репозиторий должен юридически чисто это оформлять: правка
текста LICENSE ломает машинное чтение лицензии (NOASSERTION вместо
MIT), отсутствие атрибуции = нарушение MIT, а репозиторий ВОВСЕ без
файла LICENSE юридически не open-source — юристы контрибьюторов не
могут форкнуть. Отдельный блок: QuestPDF распространяется под Community
License (не OSI), и условия редистрибуции self-contained zip обязаны
быть соблюдены и задокументированы.

Четвёртый блок, легко упустить: наш собственный код (.NET/Avalonia,
переписан с нуля — RFC-001) тоже нуждается в собственном гранте.
Upstream LICENSE покрывает только софт upstream; без нашего гранта
downstream-форки «ребят из РБ» не имеют явного права на наш код.

## 2. Решение

### 2.1 LICENSE upstream

- LICENSE upstream — ДОСЛОВНО в корне репо с commit 0, без правок и без
  добавления своих копирайт-строк внутрь (урок discussion #78: отличие
  текста от канонического MIT = GitHub показывает NOASSERTION).
- Релиз-гейт (RFC-006 §2.6, чеклист п.1): тег не ставится, пока в корне
  нет LICENSE; вкладка License на GitHub показывает «MIT» (не
  NOASSERTION) — проверяется глазами на каждом релизе.
- Атрибуция — строкой в README (раздел «License»): «Based on
  MadsLorentzen/ai-job-search (MIT), © Mads Lorentzen; adapted for
  Belarus by ThreeI». Атрибуция живёт в README, не внутри LICENSE.

### 2.2 Провенанс ассетов (выведен из оборота 2026-10-20)

- Upstream-ассеты промптов (prompts/raw/, prompts/ru/) НЕ переносятся —
  решение владельца 2026-10-20: claude-хвост продуктом не используется,
  тексты промптов для AI-цепочки пишутся свои (WP-A). Папка upstream
  OpenFonts не копируется (RFC-005 §0.7).
- Правило остаётся на случай будущего порта контента: каждый
  скопированный md-ассет несёт фиксированную 3-строчную шапку-провенанс
  (исходный путь upstream + MIT-notice + дата копирования); ТЕЛО файла
  остаётся verbatim к upstream — ручная синхронизация (§4) диффит тело,
  шапка игнорируется; адаптации помечаются как производные.

### 2.3 Лицензия нашего кода

- MIT (консистентность с upstream, простота для downstream-форков
  ребят из РБ).
- Носитель гранта — отдельный файл `LICENSE-THREEI.md` в корне:
  канонический MIT-текст + строка «Copyright (c) 2026 ThreeI and the
  ai-job-search-by contributors» (рев. 2026-10-19: расширена по черновику
  владельца, стандартная практика OSS).
  НЕ внутри upstream LICENSE (§2.1) и не в README-прозе: грант должен
  быть файлом, который юрист downstream найдёт без чтения прозы.
- Оба лицензионных файла — пристин-текст; ни в один ничего не
  дописывается (урок #78 обобщён на оба файла).
- README (раздел «License») разводит покрытия одной строкой каждая:
  адаптация upstream — LICENSE; код ThreeI —
  LICENSE-THREEI.md.
- LICENSE-THREEI.md входит в релиз-гейт (чеклист п.1) и в zip (§2.5).

### 2.4 THIRD-PARTY-NOTICES.md (третьесторонние notices)

Явный список: компонент + версия + лицензия + ссылка. Версии = стек
RFC-001 (единственный источник, не дублируем с других доков):

  права — 90 дней на переход на Professional. Редистрибуция разрешена
  ТОЛЬКО как compiled component of Derivative Application; исходники
  QuestPDF в zip НЕ включаются; proprietary notices НЕ удаляются.

Правило сопровождения: новый NuGet-пакет в дистрибутиве = строка в
THIRD-PARTY-NOTICES.md в том же коммите (документация = часть системы,
RFC-001); лицензия сверяется по источнику (NuGet/deps.dev/GitHub), не
по памяти и не по соседнему доку.

### 2.5 Условия редистрибуции zip (self-contained)

- Self-contained zip проходит как compiled component of Derivative
  Application — условие QuestPDF Community соблюдено; исходники
  QuestPDF в zip не включаются.
- End-юзеры коробки отдельной лицензии QuestPDF не требуют: по License
  Selection Guide v3.0 end users приложения не являются Developers;
  обязанность соблюдения условий лежит на дистрибьюторе (нами).
  Формулировку для DISCLAIMER.md сверить с текстом v3.0 при написании
  щитов (релизная фаза RFC-004).
- В zip НЕ включаются: исходники QuestPDF, ключи, личные данные
  (RFC-004/006). Из лицензионных текстов — только требуемые notices
  (THIRD-PARTY-NOTICES.md) и папка licenses\ (OFL-текст Lato +
  ThirdPartyNotices-dotnet.txt).
- Лицензионный комплект в корне zip: LICENSE + LICENSE-THREEI.md +
  THIRD-PARTY-NOTICES.md + DISCLAIMER.md. Полный состав zip — RFC-006
  §2.1 и чеклист п.10 (там же PRIVACY.md/SECURITY.md/
  TROUBLESHOOTING.md/README.txt); здесь не пересписываем — одно место
  истины на состав.

### 2.6 Журнал (PLAN.md §12)

- Точка форка = upstream-версия/дата + перечень наших RFC-001…007
  (сейчас — DECISIONS.md); первая запись — v0.9.0-preview (стратегия
  версий RFC-006 §2.7). До первого релиза журнал живёт в PLAN.md §12;
  после — выносится в CHANGELOG.md.
- Далее ведётся по SemVer (RFC-006): фикс адаптера = patch,
  портал/фича = minor.

### 2.7 CITATION.cff (опционально)

- CITATION.cff в корне: как цитировать проект и upstream. Бесплатно,
  добавляет академической вежливости. В релиз-гейт НЕ входит — можно
  добавить без RFC в любой момент.

## 3. Альтернативы (почему нет)

- Своя лицензия отличная от MIT: усложняет жизнь форкам и
  совместимость с upstream-ассетами. ОТКЛОНЕНО.
- Dual licensing (MIT + коммерческая): компании просто возьмут
  MIT-ветку; монетизация проекта идёт через донаты/шаблоны/консалтинг
  вне репо, не через лицензию. ОТКЛОНЕНО.
- Приватный репозиторий: продукт по замыслу публичный (RFC-006).
  ОТКЛОНЕНО.
- Один LICENSE «на всё» (дописать свой копирайт в текст upstream или
  заменить текст своим): правка ломает NOASSERTION (#78), а грант Mads
  юридически не покрывает наш код — два пристин-файла дешевле и чище.
  ОТКЛОНЕНО.

## 4. Последствия

- Синхронизация с upstream — ручная, по смыслу (ассеты не переносятся,
  §2.2; при будущем порте — дифф тела, шапка-провенанс игнорируется);
  код не синхронизируется вовсе (стек другой, RFC-001).
- Юридическая чистота публичного zip (RFC-006): лицензионный комплект
  + licenses\ внутри; тег без них не ставится.
- Триггер перепроверки: если QuestPDF изменит условия Community
  License (или в стеке поднимается версия пакета) — сверка
  совместимости (README-строка + THIRD-PARTY-NOTICES + licenses\ +
  runtime-проверка LicenseType из RFC-005) до следующего релиза.
- Личные данные вне git гарантированы RFC-004, не этим документом.
- Урок Markdig: лицензия каждого компонента сверяется по
  первоисточнику при добавлении строки в notices; «взял лицензию из
  соседнего дока» разносит ошибку по пакету (случилось с MIT→BSD-2
  между RFC-004/005 и фактом).

## 5. Отношение к другим документам

- RFC-001 (стек) — версии компонентов = источник THIRD-PARTY-NOTICES;
  там же: «LICENSE upstream — дословно; атрибуция в README».
- RFC-003 (порталы) — graveyard-практика для DISCLAIMER (провенанс
  ассетов — §2.2, выведен из оборота).
- RFC-004 (ключи и гигиена) — комплект щитов (DISCLAIMER/PRIVACY/
  SECURITY + THIRD-PARTY-NOTICES) в одном релиз-гейте; настоящий RFC
  детализирует список notices и снимает Markdig с «MIT».
- RFC-005 (экспорт) — runtime-проверка LicenseType при старте (патч
  01), Lato OFL, правило «стороннее семейство = файлы + текст
  лицензии».
- RFC-006 (публичная сборка) — состав zip (§2.1), релиз-гейт (§2.6),
  README-строки (§2.5: MIT-атрибуция + QuestPDF Community), SemVer.
- Патч 01 — лицензия QuestPDF при старте, Lato встроен.
- `PLAN.md §8` — п.1 (LICENSE дословно,
  LICENSE-THREEI, вкладка License), п.4/п.10 (лицензионный комплект и
  licenses\ в zip).
- README.md — раздел «License»: строка атрибуции upstream +
  QuestPDF Community-строка + развод LICENSE/LICENSE-THREEI.

# RFC-009 — Два ядра: опенсорс и энтерпрайз

Статус: решение владельца 2026-10-22 (чат); реализация — по фазам, без
энтерпрайз-кода «на будущее». Связано: LICENSE-THREEI.md (MIT),
architecture.md §8 (персданные), PLAN.md §7 (WP-U2 — первый шаг по этому
RFC: локальный эмбеддер с чистой лицензией).

## 1. Решение

Проект разделяется на два ядра с разной лицензией и разной судьбой:

| | Опенсорс-ядро (этот репозиторий) | Энтерпрайз-ядро |
|---|---|---|
| Продукт | рабочее место соискателя-одиночки | агентский отбор: корпус CV → пул кандидатов → объяснимый топ |
| Лицензия | MIT (обещание сохраняется) | проприетарная (BUSL / коммерческий договор) — выбирается при первом пилоте |
| Репозиторий | этот (публичный; до обкатки — приватный) | отдельный приватный репо; рождается при первом платящем пилоте, не раньше |
| Основной актив | удобство, честность, приватность (данные на диске юзера) | корпус, версионизация решений, employer-API, мультиарендность, аудит, SLA |
| Юридический контур | ToS публичных источников | персональные данные соискателей — другой класс ответственности |

## 2. Границы — что НЕ попадает в опенсорс никогда

1. Корпус CV нескольких людей; мультиарендность; роли/права.
2. Employer-API адаптеры (договорная, «обратная» сторона порталов).
3. Ранжирование пула кандидатов и реранкер (`bge-reranker-v2-m3`,
   Apache-2.0 — кандидат слоя энтерпрайз, THIRD-PARTY-NOTICES §7).
4. Аудит решений и отчёты для клиента агентства.

Персональные данные пользователей опенсорса — только на их диске
(architecture.md §8) и нигде больше; смешивание с агентским корпусом
запрещено.

## 3. Швы (уже существуют, ничего строить не нужно)

`IEmbeddingService`, `IAiChatProvider`, `IApplicationStore`,
`ILocalSecrets`, `IPortalService` — интерфейсы опенсорс-ядра; энтерпрайз
реализует их поверх общего ядра, когда появится реальный потребитель.
Общие NuGet-пакеты и submodule-хореография не создаются до того момента
(правило: «выносить общее ядро, когда оно понадобилось обеим сторонам,
не раньше»).

## 4. Лицензионная дисциплина

- Опенсорс-ядро — MIT для опубликованных версий навсегда; смена задним
  числом запрещена.
- CLA не требуется: схема «MIT-ядро + проприетарный приватный репозиторий»
  легальна по самому MIT (включение кода в закрытые продукты допустимо с
  сохранением copyright-нотисов). CLA нужен только для dual-licensing на
  том же коде — эта схема не используется.
- Каждый сторонний PR в опенсорс — только с DCO (Signed-off-by):
  дешёвая стандартная страховка права relicensing будущих версий.
- В публичных доках опенсорса не обещаются «корпоративные версии» до их
  существования.
- Товарный знак на имя проекта — отдельная задача владельца до первой
  публикации.

## 5. Порядок (фазы)

0. **Сейчас**: дожать опенсорс до прода (WP-D, гейт §8), приватный репо на
   GitHub, обкатка владельцем на реальном поиске работы — грабли =
   issues = фиксы. Ноль новых фич сверх этого.
1. **Параллельно, без кода**: деньги (ИП/счёт — критический путь, лид-тайм
   месяцы) и 5 разговоров с агентствами (сколько CV, кто отбирает, на чём,
   сколько часов, что бесит).
2. **Первый пилот** (продаётся пилот с цифрами, не код) → только тогда
   приватный энтерпрайз-репо с проприетарной лицензией на адаптеры и
   мультиарендность.
3. **Публикация опенсорса** — календарным дедлайном после обкатки
   («допилю до 90%» — главный враг плана; дедлайн лечит).

## 6. «Никогда» (жёсткие запреты)

- Энтерпрайз-код «на будущее» в этом репозитории.
- Jina в любом виде (CC BY-NC 4.0 на веса + экспортный риск из РБ; клиент
  удалён в WP-U2).
- Персданные пользователей опенсорса вне их машины.
- PR без DCO.
- Обещания энтерпрайза в публичных доках до первого платящего клиента.
