# Конфиденциальность: что происходит с вашими данными

Программа локальная: без аккаунтов, без телеметрии, без облака, без
синхронизации. Этот документ отвечает на три вопроса: что уходит во
внешние системы и кому, что остаётся на вашей машине, как удалить всё
полностью. Юридическая сторона использования сторонних сайтов — в
[`DISCLAIMER.md`](DISCLAIMER.md); хранение ключей и сообщение об
уязвимостях — в [`SECURITY.md`](SECURITY.md).

## Коротко

| Данные | Куда | Когда |
|---|---|---|
| Текст вакансии | ИИ-провайдеру из каскада | Только по вашему явному действию (ранжирование, генерация отклика) |
| Фрагменты вашего CV/профиля | Тому же ИИ-провайдеру | Только если вы сами их добавили и запустили действие |
| Поисковый запрос | Порталам из цепочки | При каждом обновлении ленты/поиске |
| Ключ API | Только своему сервису | Ключ OpenRouter — OpenRouter, ключ hirify — hirify |
| База, документы, логи, настройки | Никуда | Хранятся только в `%APPDATA%\ai-job-search-by\` |

Фоновых отправок не существует: без ваших действий программа только
*читает* публичные ленты вакансий. Телеметрии нет — и не будет
(README, «Поддержать проект»: ни подписки, ни телеметрии, ни продажи
данных).

## Что уходит в облако ИИ-провайдеров

**Что именно уходит.** Промпт, который программа собирает для ранжирования
вакансий и генерации резюме/сопроводительного письма: системный промпт
программы, текст конкретной вакансии и фрагменты вашего CV, которые вы
сами добавили в профиль. Отправка происходит **только по явному действию**
— нажатию кнопки. Программа не отправляет ничего «про запас» и не
отправляет CV автоматически при появлении новой вакансии.

**Кому уходит.** Каскад провайдеров: запрос получает тот, до кого дошла
очередь после отказов/лимитов предыдущего. В публичной коробке:

* **OrcaRouter** — анонимный эндпоинт без ключа, работает из коробки;
  запрос уходит без привязки к личности (аккаунта нет);
* **OpenRouter** — только если вы завели свой ключ; запрос уходит с вашим
  ключом, т.е. привязан к вашему аккаунту OpenRouter;
* **Cherry** — только если вы сами настроили ключ;
* **Bionic** (LM Studio, `localhost:1234`) — локальная ступень: промпт
  не покидает вашу машину в принципе. По умолчанию выключен, включается
  галочкой в настройках; включённый — первая ступень каскада.

Ступени OmniRoute и GLM принадлежат приватному профилю автора (`me`) и в
публичный дистрибутив не входят: в вашей сборке их нет, и промпты к ним
не публикуются. Профили `me`/`public` описаны в DECISIONS.md (RFC-002 §2).

**Как это обрабатывается на той стороне.** Дальше запроса вы не
контролируете: провайдер обрабатывает его по *своей* политике
конфиденциальности (сайт провайдера → Privacy Policy). Программа не
может гарантировать удаление промпта у провайдера. Практический совет:
кладите в профиль только те данные о себе, которые готовы увидеть
обработчики запроса — как при отправке отклика живому человеку.

**Что не уходит никогда:** ключи API (в промпты и логи не попадают —
требование к коду проверяется тест-гардом), содержимое локальной базы
`jobs.db`, файлы документов, журналы, настройки. Ключ отправляется
только адресату по назначению — ключ ИИ-провайдера выбранному
провайдеру, ключ портала с официальным API — самому порталу; никаким
третьим лицам (SECURITY.md, «Как устроено хранение ключей»).

## Что уходит порталам

**Цепочка по умолчанию — 6 международных фидов**, все работают без
авторизации (RemoteOK, Remotive, Himalayas, Jobicy, WeWorkRemotely,
NoDesk). Наружу к порталу уходит только HTTP-запрос за лентой/поиском с
вашим поисковым запросом. Аккаунтов нет — программе нечего передавать
порталу о вас: ни имени, ни email, ни резюме.

**Исключение — hirify.** Официальный AI-agent доступ с *вашим личным
ключом* (платный тариф, включается вручную, по умолчанию выключен).
Ему видны ваши поисковые запросы и ваш ключ — это условие его
собственного ToS, разрешающего автоматизацию личного поиска.

**Автоматической подачи откликов нет** — намеренно (README, «Что НЕ
входит в v1»): программа никогда ничего не отправляет на сайты вакансий
от вашего имени. Резюме и письма собираются локально и экспортируются в
файлы, а не постятся в формы.

## Что остаётся локально

Всё, что создаёт программа, живёт в `%APPDATA%\ai-job-search-by\`
и в папке самой программы — больше нигде:

| Файл/папка | Что это | Секреты |
|---|---|---|
| `settings.json` | Настройки без секретов | Можно прикладывать к баг-репортам |
| `local.json` | Ключи API | Не прикладывать никогда |
| `rate-limit.json` | Кулдауны провайдеров | Нет |
| `jobs.db` (+ `-shm`/`-wal`) | База вакансий, история запросов и откликов | Личные данные |
| `documents\` | Сгенерированные резюме и письма | Личные данные |
| `logs\` | Журналы работы | Ключи не пишутся (тест-гард) |

В папке репозитория и рядом с exe личных данных нет вообще: онбординг
физически не умеет писать вне белого списка `%APPDATA%\ai-job-search-by\**`
(проверяется xUnit-гардом). ATS-проверка PDF — локальная: PdfPig читает
файл обратно в текст, к сети не обращается и третьим лицам резюме не
отправляет.

## Как удалить всё полностью

1. Удалите папку программы.
2. Удалите `%APPDATA%\ai-job-search-by\` — база, документы, ключи,
   журналы и кулдауны живут только там; после этих двух шагов машина
   чистая.

Удаление локальной копии не удаляет историю у облачных провайдеров:
если вы пользовались ключом OpenRouter (или другим провайдером с
аккаунтом), запросы и их обработка — предмет политики того сервиса,
удалять нужно в его кабинете. У анонимного OrcaRouter аккаунта нет.

## Репозиторий и дистрибутив

В git-репозитории и в релизном zip ключей и личных данных нет по
построению: `.gitignore` закрывает конфиги с ключами; CI-джобы
`secrets-guard` (ключеобразные паттерны и личные данные в диффе) и
релиз-гейт проверяют это до публикации. Распаковка в `Program Files`
не влияет на приватность, но ломает запись конфигурации — см.
[`troubleshooting.md`](troubleshooting.md).

`DECISIONS.md` до кода.
