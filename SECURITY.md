# Политика безопасности

## Сообщить об уязвимости

**Не заводите публичный issue на уязвимость.** Напишите в
приватный security advisory — вкладка **Security** репозитория →
«Report a vulnerability» — это самый надёжный канал. Если он недоступен — в личные сообщения автору репозитория.

Опишите:

* что делает уязвимость и на что влияет;
* шаги воспроизведения (лучше — на тестовом окружении, не на реальных данных);
* версию (номер релиза) и ОС.

**Что ожидается:** ответ в течение 7 дней. Подтверждение, что сообщение
принято, придёт даже если исправление ещё не готово.

**Не сообщайте о проблемах безопасности публично**, пока не выйдет релиз с
исправлением. Особенно: если проблема позволяет перехватить ключи API или
прочитать чужие данные — не публикуйте PoC, который можно скопировать.

## Что считается уязвимостью

* **Утечка ключей API:** ключ попадает в журналы
  (`C:\Users\<юзер>\ai-job-search-by\logs\`), в экспортированный файл, в отчёт об
  ошибке или уходит любому адресату, кроме того, которому вы его доверили.
* **Утечка локальных данных:** доступ к `C:\Users\<юзер>\ai-job-search-by\`
  (`state\local.json` с ключами, `data\ai-job-search-by.db`,
  `logs\`) сверх прав текущего пользователя.
* **Выполнение кода из недоверенного источника:** адаптер портала или
  экспортёр исполняет то, что пришло из сети.
* **Отправка ваших данных вовне без вашего действия** — все облачные
  отправки запускаются только явными кнопками (PRIVACY.md).
* **Нежелательная отправка данных вовне:** персональные данные уходят
  AI-провайдеру тогда, когда пользователь этого не инициировал.

## Что НЕ является уязвимостью

* **SmartScreen ругается на неподписанный exe.** Это ожидаемое поведение,
  описанное в [docs/INSTALL.md](docs/INSTALL.md#smartscreen--windows-защитила-ваш-компьютер)
  (в дистрибутиве — `TROUBLESHOOTING.md`). Не уязвимость.
* **Портал отдаёт 0 вакансий или ломает вёрстку.** Это поломка адаптера,
  не уязвимость — пишите через шаблон «портал сломался».
* **Программа пишет данные в профиль пользователя без шифрования.** На типовой
  однопользовательской Windows-машине это норма. (Шифрование в v1 не
  планируется — отдельное решение, если появятся основания.)
* **Программа обращается к сторонним сайтам.** Это её назначение; условия
  использования описаны в [`DISCLAIMER.md`](DISCLAIMER.md).

## Как устроено хранение ключей

* Ключи хранятся только в `C:\Users\<юзер>\ai-job-search-by\state\local.json`.
  Рядом `state\keywords.json` и счётчики квот — **без секретов**: их можно прикладывать к
  баг-репортам. `local.json` не прикладывайте никогда.
* Ключи **не пишутся в журналы** — это требование к коду, оно проверяется
  тестом-guard'ом на логгере.
* Ключи отправляются **только адресату по назначению**: ключ AI-провайдера —
  выбранному провайдеру, ключ портала с официальным API (hirify) — самому
  порталу. Никаким третьим лицам.
* Ключи не попадают в репозиторий: файлы с ключами перечислены в
  `.gitignore`, плюс CI-джоб `secrets-guard` блокирует merge, если в
  индексе git оказались файлы с ключами или следы `sk-` / `Bearer` /
  `app_key`.
* В дистрибутивном zip ключей и локальных настроек нет по построению —
  это проверяется релиз-гейтом.
* При выгрузке отчёта об ошибке проверьте вычитку сами: журнал не должен
  содержать ключей, но лишний взгляд не помешает.

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| Последний релиз | ✅ |
| Предыдущий релиз | ⚠️ по запросу, без обещаний |
| Всё, что старше | ❌ |

Проект хобби: поддерживается **только последний релиз**. Исправление
выходит очередным релизом (SemVer) — обновиться проще,
чем ждать бэкпорта в старую версию.
