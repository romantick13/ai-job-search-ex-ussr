# Каталог порталов

Машинно-читаемый источник правды — [`config/registry.json`](config/registry.json).
Этот документ — человекочитаемая часть того же набора данных.

## Как читать статусы

| Поле | Значения | Что значит |
|---|---|---|
| `access` | `none` | Вакансии видны без входа в аккаунт и без ключа |
| | `account` | Нужен аккаунт пользователя (в v1 не поддерживается) |
| | `official_api` | Есть официальный API — используем его, не скрапим |
| | `rss` | Есть публичная RSS/Atom-лента |
| `tos_status` | `allowed` | Правила сайта не запрещают автоматический сбор; в реестре обязана быть цитата/ссылка (`tos_evidence`) + дата проверки |
| | `official_api` | Доступ идёт через официальный API — ToS соблюдается по определению |
| | `forbidden` | Явный запрет → портал в [graveyard](portals-graveyard.md), исключён навсегда |
| | `unverified` | Не проверено → **выключен по умолчанию** |
| `default_enabled` | `true`/`false` | Попадает ли в цепочку по умолчанию |

**Правило включения в цепочку по умолчанию:**
`tos_status ∈ {allowed, official_api}` **И** `access ≠ account` **И**
`default_enabled = true` **И** `adapter_implemented = true`.

Всё, что не проходит этот фильтр, в цепочку не попадает, но остаётся
доступным в интерфейсе для ручного включения — кроме `forbidden`, который
исключён полностью. Состояния `owner_override` больше нет: r21 оно жило
один день (praca.by подключался решением владельца) и было отозвано тем
же решением — адаптер вырезан, портал вернулся в чистый `forbidden`
(полная история — [graveyard](portals-graveyard.md), раздел praca.by).

r21 (решение владельца): **в цепочку по умолчанию не входит никто** — все
чекбоксы выключены, юзер собирает цепочку сам (выбор запоминается в базе).

## География: страна источника, место работы и удалёнка

Частая путаница — три разные «страны», которые не стоит смешивать:

* **Страна источника** — чьё зеркало hh-группы открыто: `rabota.by` — это
  белорусский сайт, но база группы общая (hh.ru, hh.kz, hh.uz, hh.ge), и без
  параметра региона в выдаче «Минска» прилетают Казань и Ташкент.
* **Место работы** — то, что написано в локации вакансии. Программа
  повторяет поведение сайта в браузере: к каждому поиску добавляется регион
  «Беларусь» (`area=16`), поэтому выдача совпадает с тем, что человек видит
  на rabota.by сам.
* **Разрешённая страна работы** — фильтр пользователя. Дефолт — Беларусь +
  Россия (решение после живого прогона, где Ташкент и Алматы доходили до
  окна). Удалёнка и гибрид проходят, только если страна работы из
  разрешённых: удалённая вакансия «из любой точки мира» с формулировкой
  «anywhere» без привязки к стране считается допустимой, а «удалённо, офис в
  Ташкенте» — прячется. Локация авторитетнее текста описания: минская
  вакансия с «офисами в Ташкенте» в тексте не прячется.

Для международных remote-фидов (🌍 в таблице) фильтр работает так же:
каждая строка проходит гео-разбор локации; вакансия без всякой локации
показывается (её видит пользователь сам — скрыть молча нельзя, серые строки
и протокол это отражают).

## Заметки по конкретным порталам

### Belmeta — запрещён: robots.txt закрыл вакансии для роботов

Проверен 2026-10-19 (ToS + robots.txt + партнёрская страница; программные
снимки — в локальном архиве владельца, в репо не публикуются). Результат отрицательный: `User-agent: *` → `Disallow: /vacansii*`
и `Disallow: /jobdesc` — поиск и карточки вакансий закрыты для всех роботов
без исключений; ToS добавляет запрет «действий за рамками нормального
(целевого) использования». Статус в реестре — `forbidden`, адаптер
не подключается. Полный разбор с цитатами —
[graveyard](portals-graveyard.md#belmetacom--вакансии-закрыты-для-роботов-в-robotstxt).

### Rabota.by — решено: API только для работодателей

Соглашение разработчика (<https://dev.rabota.by/admin/developer_agreement>,
приказ №4-О от 09.02.2022) процитировано дословно 2026-10-19: п.1.1 —
регистрация приложения и уникальный API-ключ; п.1.5 — «Пользователем Сервиса
могут быть только организации-работодатели»; п.1.3/1.6 — отказ без объяснения
причин. Соискательский инструмент под эти условия не подпадает. Статус
`official_api` сохранён, API-адаптера нет — разбор в
[graveyard](portals-graveyard.md#rabotaby--официальный-api-но-только-для-работодателей).

**Что изменилось после этого вердикта (2026-10-27/28):** выяснилось, что
HTML-выдача группы hh для человека открыта без регистрации (живая проверка:
939 787 вакансий без капчи), и владельцем принято решение о браузерной
эмуляции личного просмотра выдачи — это отдельный адаптер `hh-by` (см.
следующий раздел), а не «HTML-скрапинг взамен API». Ссылки на страницы
вакансий открываются вручную; автоматической подачи откликов нет.

### HeadHunter.by — отложен: API закрыт платформой

Официальный API требует OAuth-регистрации приложения. Публичный поиск вакансий
группы hh закрыт с апреля 2026: неавторизованный GET /vacancies возвращает 403
(обнаружено экспериментально, публично задокументировано в августе 2026).
Регистрация приложения каждым пользователем — не v1-сценарий. В v1 портал
выключен; перепроверка раз в квартал — вдруг откроют.

### Зеркала hh — текущий адаптер hh-группы: браузерная эмуляция выдачи (2026-10-29)

Четыре зеркала — по одному на страну: hh.ru
(Россия, area 113), HH.by + rabota.by (Беларусь, area 16), hh.kz
(Казахстан, area 40), hh.uz (Узбекистан, area 97); коды регионов —
справочник api.hh.ru/areas/countries. С r21 все чекбоксы по умолчанию
выключены: зеркало попадает в цепочку только по галочке пользователя
(выбор запоминается в базе). Живая проверка 2026-10-28/29:
счётчик «Найдено 159 вакансий», 20 карточек на страницу, нумерованный
пагинатор; выдача открыта без регистрации и капчи. Другие бывшие республики
СССР зеркал группы hh не имеют (hh.kg/hh.tj не отвечают, hh.md/hh.ge/hh.am —
чужие сайты).

| Поле карточки | Значение |
|---|---|
| id | `hh-ru`, `hh-by`, `hh-kz`, `hh-uz` (по чекбоксу на страну) |
| access | `scrape` — браузерная эмуляция: заголовки обычного браузера, запрос только страниц выдачи своих поисковых слов (`text` + `area` кода страны) |
| что запрашивается | план страниц из счётчика «Найдено N вакансий» и пагинатора `data-qa="pager-page"`; страницы кэшируются; карточки разбираются из кэша; вкладки вакансий НЕ открываются |
| чего не делается | вход в аккаунт; выгрузка каталога; автоматическая подача откликов (отклик — руками на сайте, ссылка — скрепка в строке) |
| antiBot | каждая следующая страница выдачи — новая вкладка с рваной паузой 5–25 с (мгновенная скачка приводит к щиту сайта); 403/429/503 → одна ретрай-пауза; плохая страница кэша пропускается с warn; смена вёрстки → честный `ParseFailedException` («вёрстка выдачи сменилась»), остальные порталы дорабатывают |
| tos_status | `allowed` — оценка проекта (НЕ юридическая гарантия); полная аргументация и границы — в `tos_evidence` реестра (`config/registry.json`) |
| дедуп | канонический URL + «название + работодатель» (перепосты hh и сеть филиалов «Компания. Отдел» — одна строка) |
| география | каждое зеркало ищет в своей стране (`area`); чужие страны — гео-фильтр (дефолт Беларусь + Россия) |
| дефолт цепи | `default_enabled: false` (r21: все чекбоксы выключены — включается галочкой юзера) |
| честное ограничение | правила группы hh меняются; при блокировке или смене правил адаптер помечается/исключается — причина видна в протоколе |

### Международные фиды — открытые данные, а не скрапинг

RemoteOK, Remotive, Jobicy публикуют открытые API, документированные самими
порталами и предназначенные для программного потребления; Himalayas,
WeWorkRemotely, NoDesk — публичные RSS-ленты. Это не скрапинг HTML: источник
сам предоставляет структурированные данные. Ссылки на каждый источник и даты
проверки — в `tos_evidence` реестра. Релевантность для РБ (двойной
гражданин, локация, язык) — фильтрами на нашей стороне, а не скрапингом
чужих страниц.

### HN: Who is hiring? — тред, не портал

Публичный Algolia API Hacker News отдаёт комментарии ежемесячного треда
«Who is hiring?». Это ценный источник, но он не «портал вакансий» и в счётчик
порталов не входит. Включается пользователем вручную.

### Hirify.me — allowed: автоматизация личного поиска через официальный ключ

Проверен 2026-10-19 по всем фронтам:

* **ToS найден и процитирован**: «Terms of Service» (Effective Date 18.08.2026,
  `hirify.me/terms-of-service`). §3.1: «We do not forbid automating a job
  search. If you are looking for work for yourself and an AI agent does part
  of that work, it is allowed on one condition: the agent goes through the
  official AI agent access, not around the interface. The official access is
  set up in the AI agent access section and works with a personal key...»
  Итог §3.2: «In short: searching for work for yourself is fine in any way
  you like, including through an agent».
* **Официальный канал существует**: раздел «AI agent access» на сайте
  (личный ключ, дневные лимиты видны там же) + npm-пакет `hirify-cli`
  («Search jobs... from a terminal or an AI agent. For unattended work,
  obtain a key at API access»). Это первый проверенный источник, чьи правила
  написаны ровно под наш use case.
* **robots.txt** (снят 2026-10-19): `Allow: /` для страниц вакансий, закрыты
  только служебные пути и `/api/*` (внутренний API приватный — что совпадает
  с ToS §3.2).
* **Что запрещено (§3.2)**: обход официального доступа (симуляция запросов
  веб-приложения, cookies/сессии/токены); сбор каталога под чужой
  продукт/агрегатор/бот; обход дневных лимитов; перепубликация вакансий без
  ссылки на оригинал.

**Следствие для архитектуры**: старый HTML-адаптер (таргетил hirify.co)
разобран; новый пишется ТОЛЬКО под официальный AI-agent API с личным ключом
пользователя. Дневные лимиты читаются из кабинета (принцип «числа в
рантайме»). В authless-счётчик не попадает (нужен ключ) — включается
вручную, по модели «есть ключ — есть источник».

### Wellfound / Instahyre / Paraform — запрещены (партия 2026-10-19)

Три новичка проверены в один день и все трое — в graveyard, каждый с
дословной цитатой:

* **Wellfound** (`wellfound.com`, ex-AngelList): ToS запрещает
  harvesting/collection/«scraping» и любые автоматические системы (spider,
  robot, offline reader); страница /tos без браузера отдаёт 403 «Security
  Check» (DataDome) — юридический запрет усилен техническим.
* **Instahyre** (`instahyre.com`, Индия): ToS §8.3.5 — запрет crawl/spider,
  §8.3.6 — запрет «access... harvest or scrape or otherwise extract in any

## Как проверить новый портал (чеклист)

1. Найти действующие ToS / пользовательское соглашение / robots.txt.
2. Зафиксировать: название документа, номер пункта, дату редакции, точную
   цитату — в `tos_evidence` реестра, с датой проверки.
3. Определить `access`: `none` / `account` / `official_api` / `rss`.
4. Определить `tos_status`:
   * явно разрешает автоматический доступ (или публикует открытый API/ленту
     для программного потребления) → `allowed`;
   * явно запрещает скрипты/парсинг → `forbidden` + запись в graveyard;
   * ничего не сказано → `unverified` + **выключен по умолчанию**.
5. Внести в `config/registry.json`.
6. Написать адаптер, проверить на 2–3 реальных запросах.
7. Прогнать `python tools/gen_readme_counters.py` — счётчики в README
   обновятся; `allowed` без `tos_evidence` скрипт не пропустит.

**Правило по умолчанию — запрет.** Пока статус не `allowed` или
`official_api`, портал не включается в цепочку. Это медленнее, но это
единственный способ не обманывать пользователя обещанием «не нарушаем ToS».
