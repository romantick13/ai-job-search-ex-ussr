# Порталы в боксе: почему отключены

Здесь живут порталы, которые **нельзя** использовать автоматически — потому что
это прямо запрещено их правилами, либо потому что статус правил не проверен.

Список — не формальность. Каждая запись содержит цитату на конкретный пункт
соглашения, чтобы решение можно было перепроверить, а не принять на веру.

Пути вида `evidence/…` в тексте ниже — локальный архив владельца:
программные снимки чужих документов в публичном репозитории не хранятся
(здесь — дословные цитаты, ссылки и даты проверок).

**Правило проекта:** портал из этого списка не может попасть в цепочку по
умолчанию. Если он там оказался — это баг, а не «особый случай». Скрипт
`tools/gen_readme_counters.py` валидирует реестр и падает на таком расхождении.

## praca.by — запрещено явно

**Домен:** praca.by (Беларусь; сайт ООО «ПРАЦА БАЙ», Минск, «Вся Беларусь»)
**Статус:** `forbidden` — запреты сайта в силе, адаптер не используется.
**Версия документов:** редакция от 01.12.2025.

### Запреты (в силе)

Запрет зафиксирован **дважды**, в двух независимых документах:

**1. «Соглашение об использовании портала», §7.7:**

> «Не допускается использование программных средств (скриптов, роботов) для
> считывания или сбора информации»

**2. «Пользовательское соглашение», §5.1.11** — отдельный запрет на парсинг
(дословно, снято с praca.by/info/polzovatelskoe-soglashenie 2026-10-19;
УТВЕРЖДЕНО приказом директора ООО «ПРАЦА БАЙ», действующая редакция от 01.12.2025):

> «5.1.11. использовать функции парсинга/программы парсинга, любых программных
> средств (скриптов, роботов) для считывания или сбора информации (данных)
> из Системы;»

Рядом — усиливающие пункты того же раздела: §5.1.9 «использовать программные
средства, имитирующие работу пользователя в Системе», §5.1.10 «использовать
анонимные прокси-сервера», §5.1.12 «использовать плагины в Системе, кроме тех,
которые не осуществляют парсинг, копирование из Системы». Полный снимок
документа: `evidence/praca-agreement-2026-10-19.txt`.

### Почему это запрет, а не «ну и что»

* Формулировка «скрипты, роботы» покрывает ровно то, что делает адаптер
  этого проекта. «Технически я просто HTTP-запросы» — не аргумент: правила
  сайта не различают реализации.
* Запрет двойной — в двух документах с разными редакциями, — значит при
  смене версии соглашения шанс, что запрет исчезнет, стремится к нулю.

## belmeta.com — вакансии закрыты для роботов в robots.txt

**Домен:** belmeta.com
**Статус:** `forbidden` — исключён из цепочки, адаптер не подключается.
**Версия документов:** «Условия использования Cайта Belmeta.com» (приказ
директора ООО «Белмета Бай» от 20.02.2025 №02-ОД, действует с 11.03.2025);
robots.txt снят 2026-10-19.

**1. robots.txt — прямой запрет для всех роботов на страницы вакансий:**

> `User-agent: *`
> `Disallow: /vacansii*` — страницы поиска вакансий
> `Disallow: /jobdesc` — карточки вакансий

(SEO-ботам — dotbot, SemrushBot, BLEXBot, PetalBot и др. — запрещён весь сайт:
`Disallow: /`.)

**2. «Условия использования», раздел «Обязанности Пользователей»:**

> «...не совершать любых действий, выходящих за рамки нормального (целевого)
> использования Сайта»

> «Не производить поиск, сбор и систематизацию данных других Пользователей,
> в т.ч. посредством использования компьютерных программ ("ботов")»

**3. Раздел «Интеллектуальная собственность на Сайт»:**

> «При полном или частичном воспроизведении, копировании, переработке,
> распространении... требуется предварительное письменное согласие Оператора.
> При размещении на Сайтах третьих лиц Карточек вакансий, Карточек Работодателей
> ссылка на Сайт обязательна.»

**Обоснование решения:** адаптеру нужны ровно те пути, что закрыты в robots.txt
(`/vacansii*`, `/jobdesc`), причём закрыты для `User-agent: *` — без исключений
для добросовестных ботов. Игнорирование robots.txt — сознательный обход воли
владельца, несовместимый с обещанием README «не нарушаем правила источников».
То, что в самом ToS нет дословного слова «парсинг», роли не играет: запрет
роботам выражен техническим стандартом, а «рамки нормального использования» —
вторая линия обороны. Партнёрская страница belmeta (снята 2026-10-19) принимает
XML-фиды от ИСТОЧНИКОВ вакансий и канала для потребителей не предлагает.
Единственный путь вернуться: официальный публичный API/RSS или письменное
согласие Оператора. Снимки: `evidence/belmeta-terms-2026-10-19.txt`,
`evidence/belmeta-robots-2026-10-19.txt`, `evidence/belmeta-partners-2026-10-19.txt`.

## instahyre.com — прямой запрет crawl/spider/harvest/scrape

**Домен:** instahyre.com (Индия)
**Статус:** `forbidden` — исключён из цепочки, адаптер не подключается.
**Версия документов:** «Instahyre Terms of Use»
(https://www.instahyre.com/terms/), редакция с 18.08.2025.

§8.3, снято дословно 2026-10-19:

> п.5: «use or attempt to use manual or automated software, devices, or other
> processes to crawl or spider any part of the Platform»

> п.6: «access, navigate, search, copy, monitor, download, harvest or scrape
> or otherwise extract in any manner, any Content from the Service»

> п.3: «bypass any measures Instahyre may use to prevent or restrict access
> to the Service»

**Обоснование решения:** двойной запрет — и на инструменты (crawl/spider),
и на результат (harvest/scrape «in any manner»). robots.txt (снят
2026-10-19) запретов не содержит (только Sitemap), но ToS сильнее robots.
Дополнительно §2.2: платформа не гарантирует уместность контента вне Индии
(«makes no representation that the content... is appropriate to be used or
accessed outside India») — релевантность для РБ минимальна, риск не
окупается. Снимок: `evidence/instahyre-robots-2026-10-19.txt`.

## wellfound.com — запрет harvesting/scraping + анти-бот DataDome

**Домен:** wellfound.com (ex-AngelList Talent)
**Статус:** `forbidden` — исключён из цепочки, адаптер не подключается.
**Версия документов:** «Talent General Terms» (https://wellfound.com/terms).

Цитаты, снято дословно 2026-10-19:

> запрет «copy, disclose or distribute Content except as expressly permitted
> by the Terms (including through the use of automated or non-automated
> harvesting, collection or “scraping”) or otherwise use the Site or Services
> for competitive purposes»

> запрет «use any automated system (including a spider, robot, or offline
> reader) to access the Site or Services in a manner that takes more
> bandwidth or produces greater load on Wellfound's network...»

**Обоснование решения:** юридический запрет усилен техническим: страница
/tos без браузера отдаёт 403 «Security Check» (DataDome) — платформа активно
рвёт автоматизированный доступ, чего мы обходим никогда. robots.txt (снят
2026-10-19) закрывает `/_jobs/` и служебные пути. Снимки:
`evidence/wellfound-tos-terms-2026-10-19.txt`,
`evidence/wellfound-robots-2026-10-19.txt`.

## paraform.com — «crawls, scrapes, or spiders» в явном списке запрещённого

**Домен:** paraform.com (рекрутинговый маркетплейс)
**Статус:** `forbidden` — исключён из цепочки, адаптер не подключается.
**Версия документов:** «Terms of use» (https://paraform.com/terms).

Цитата, снято дословно 2026-10-19, список запрещённых действий:

> «“crawls,” “scrapes,” or “spiders” any page, data, or portion of or
> relating to the Services or Content (through use of manual or automated
> means)»

> «copies or stores any significant portion of the Content»

**Обоснование решения:** запрет сквозной — «manual or automated means», то
есть закрывает даже «руками с блокнотом», не то что адаптер. Плюс запрет
хранения значительной части контента. Снимки:
`evidence/paraform-tos-terms-2026-10-19.txt`,
`evidence/paraform-robots-2026-10-19.txt`.

## rabota.by — официальный API, но только для работодателей

**Домен:** rabota.by
**Статус:** `official_api`, но `default_enabled: false`, адаптер не
подключается — API юридически недоступен для соискательских инструментов.
**Версия документов:** «Условия использования сервиса API»
(dev.rabota.by/admin/developer_agreement, приказ №4-О от 09.02.2022).

Цитаты (снято дословно 2026-10-19):

> п.1.1: «...пройти процедуру регистрации программы для ЭВМ... на сайте
> rabota.by по адресу https://dev.rabota.by и получить уникальный API-ключ»

> п.1.5: «Пользователем Сервиса могут быть только организации-работодатели,
> использующие Сервис только для целей привлечения потенциальных работников
> и их последующего трудоустройства в организацию-Пользователя.»

> п.1.6: «...rabota.by вправе в любое время отказать в использовании Сервиса
> ... без какой-либо компенсации или возмещения в связи с этим.»

**Обоснование решения:** наш инструмент — для соискателя, а Сервис по соглашению
открыт только организациям-работодателям для целей найма. Регистрация под ложным
предлогом — нарушение соглашения с первого дня. HTML-скрапинг взамен API тоже
невозможен: rabota.by — группа hh, публичный поиск закрыт с 04.2026.
Перепроверять при появлении соискательского API или изменении п.1.5. Снимок:
`evidence/rabota-dev-agreement-2026-10-19.txt`.

## Закрытые самими платформами (не наша юридическая оценка)

Раздел для порталов, которые не работают по вине самой платформы. Это не
`forbidden` и не `unverified` — юридического запрета нет, но источник мёртв.

### Группа hh (hh.ru / hh.by / rabota.by / jobs.tut.by) — публичный поиск закрыт

**Статус:** поиск вакансий без авторизации закрыт платформой с апреля 2026
года: неавторизованный `GET /vacancies` api.hh.ru возвращает 403 Forbidden
(обнаружено экспериментально, публично задокументировано в новости Хабра
11.08.2026 «HH.ru закрыл публичный API поиска вакансий»). Официальный путь —
регистрация приложения, что несовместимо с обещанием «работает без ключей из
коробки».

**Дополнительный факт:** домены jobs.tut.by, rabota.tut.by, job.tut.by
принадлежат группе hh (перечислены в permittedHosts api.hh.ru) — отдельным
«не-hh» источником они не являются.

**Следствие для проекта:** hh-by и зависимые домены выключены в реестре
(`default_enabled: false`), перепроверка раз в квартал. Вопрос rabota.by
закрыт 2026-10-19 отрицательно: официальный API по соглашению разработчика
доступен только организациям-работодателям (см. запись выше).
